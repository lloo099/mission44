## 1. 一句话定位

主动式 agent 系统里,**人类注意力是被 N 条并发工作流争抢的、有限且会排队的资源**;本项目把准入(接不接这件事)、调度(谁占 worker 槽)、呈现(什么现在送到人面前)当作**一个**联合资源分配问题来形式化、测量和学习,替代目前全靠手写提示词与魔法数字的做法。

> **⚠ 本节已被 M0 核实取代,不要按原样引用。** 读到 arXiv 2402.12237 原文后确认,上述命题的大部分已被在先工作占据(§6.1)。**替代定位句见 §6.2 末:Lykouris & Weng 在「人类是完美且外生的 oracle」前提下解决了准入+调度+学习,而 agent 把关正是人类既不完美、也不外生的场景。** 裁决见 §12.1:路线甲可行。本节文字保留,仅作为原始主张的记录。

## 2. 问题陈述:三个可指认的病灶

主动式 agent 每天反复做同一个判断:**现在就做 / 问人一句 / 先不出声**。这个判断今天由手写规则加一个三档开关决定,而**没有任何指标能衡量写得对不对**。`dsh-superagent` 把机制完整公开,于是病灶可以被精确指认(以下均〔一手〕):

### 2.1 出厂默认档位是"永远不行动",且不产生学习信号

`docs/002-authorization.md`:接受模式有 `off` / `observe` / `auto` 三档,**`observe` 是默认**。该档下推断候选照常评估,正向评估被**记录为 ignore 并标注 `"would accept"`,不接受任何工作**。文档要求"从 `observe` 起步,复核记录下来的 Decision 之后再切到 `auto`"。

但文档**没有给出任何判据说明什么时候算复核够了**。后果有两层:

1. 交付层面:留在 `observe` 则主动能力产出恒为零;
2. **信息层面:`observe` 下动作从未执行,因此被评估的规则永远不产生结果标签**。出厂默认配置**在构造上就是信息饥饿的**——它既不交付价值,也不积累能用来改进自己的证据。

### 2.2 槽位限制约束的是 agent 并发,没有任何机制约束人类负载

`docs/007-architecture.md` 给出并发表:`assessment` 4、`delivery` 4、`relay`/`notice`/`reply` 各 1、`launch` 为空闲 worker 槽数;`WorkerSlots` 在 launch 或 wake 前预留容量,**一条人类消息可以多占一个槽超出 `maxWorkers`,且 wake 优先于 launch**。`docs/003-execution.md`:一个 Ticket **从 launch(含 preparation)起、在每个活跃回合中持续占用一个 worker 槽**。

而交接规则是:Ticket 在 `ready` Report 或提问后交给人(除非有新 Input 到达),任何 `blocked` / `failed` Report 之后也交给人。

两者合起来意味着:**5 个 Ticket 同时完工就是 5 个交接同时到达同一个人**。槽位机制精确地限制了 agent 侧并发,但 host 侧**不存在"这个人当前已饱和"这一概念**,人类负载没有任何节流。

### 2.3 呈现规则是未经测量的魔法数字

`docs/002-authorization.md`:panel 只在 Decision 为 `unavailable`、**年龄小于 24 小时**、是其 Thread 上最新、未被 dismiss、且 Thread 既不在排队也不在评估时,才请求人类注意力。`evals` 健康项报告**最近一小时**未解决的 unavailable Decision。

24 小时与 1 小时这两个阈值没有任何测量支撑。它们是合理的工程直觉,但正是"无法判断自己写得对不对"的典型样本。

> 补充一条机制性风险,与本提案目标直接相关〔一手〕:`docs/007-architecture.md` 明确"目前没有任何机制删除旧记录,因此多数表无界增长"。长期运行下,注意力相关的历史统计本身会变成成本。

## 3. 时机:为什么现在做

三条同时成立,构成一个窄窗口:

1. **机制第一次可读可改**〔一手〕。`dsh-superagent` 以 MIT 发布,把准入模式、Mandate 与 Policy 版本、槽位与并发、Ticket 七档 stage、panel 注意力规则全部写成文档。这类系统此前只存在于各家内部,研究者无法指认其决策点。
2. **目标函数已被写下,但从未被优化**。`docs/000-philosophy.md` 的原则是 **"Take as little human attention as possible, and give as much value as possible"**,并明确衡量标准是"一条消息消耗的注意力 vs 它交付的价值,**而不是 agent 完成了多少工作**",还给出"the right help at the right time, and nothing at any other time"〔一手〕。而按二手报道,配套设计文章《Exploring Super-agent Design: Towards a More Autonomous Agent System》(约 2026-10-31)称**一个人通常只能盯 3–5 个并发 agent 会话**,其实验为**合成负载、以"消耗时间的工具"模拟写代码**,只测调度与协调而非代码质量,报告中位完成时间比 neutral-prompt 基线低 **39.2%**、cache 读约 3.8 倍〔二手,数字待核〕。

   这组事实的含义很具体:**一句提示词就拿到 39.2%,说明这个杠杆有效且几乎未被开发,而他们自己的评测承认是合成的。**
3. **文献三面包夹,中间是空的**。见 §6。

## 4. 形式化:ABO

### 4.1 决策变量

离散时间。外部事件流(GitHub 事件 → Trigger)到达,router 在每一步面对三类决策:

| 决策 | 动作空间 | 对应的真实机制〔一手〕 |
|---|---|---|
| **准入** $a^{\text{adm}}$ | {拒绝, 仅记录, 接受} | Eval → Decision → accept 创建 Ticket/Mandate/Assignment |
| **调度** $a^{\text{sch}}$ | 启动顺序、wake 与 launch 的优先、是否让位 | `WorkerSlots`、`maxWorkers`、wake 优先于 launch |
| **呈现** $a^{\text{sur}}$ | {立即送, 并入下一批, 延后, 暂不送} × 粒度(摘要/全量 diff) | Ticket stage 决定"谁该管"、panel 的注意力规则 |

### 4.2 人类模型(本提案的核心建模对象)

把操作者建成**单服务器排队系统**,四个要素:

1. **有限服务率** $\mu$(件/小时);
2. **切换成本** $s$:相邻处理的两件事属于不同 Ticket 时产生。按二手的实践观察,切换的代价主要不在切换动作本身,而在**重新装载该任务历史与先前决策的恢复时间**〔二手〕;
3. **质量随负载退化** $q(\ell)$:审查准确率随瞬时负载 $\ell$ 下降。这一项是"呈现更多不等于更安全"的来源〔二手,且为建模结论,见 §12〕;
4. **可用窗口**:从 trace 中维护者的真实活跃时段估计,不假设人随时在线。

### 4.3 目标

$$\max\ \mathbb{E}\Big[\textstyle\sum_t \text{value}_t\Big] \quad \text{s.t.}\quad \text{注意力消耗率} \le B$$

**但主结果不报单一数字,而是扫 $B$ 得到的价值—注意力前沿。** 理由直接来自 philosophy 文档:最优工作点依操作者而异,"值不值得打扰"本身是操作者的偏好〔一手〕。注意力按**可数单位**计量,不引入主观评分:

- 需要人处理的条目数;
- 送达的通知数;
- 人必须读的 review 量(diff 行数 / token);
- 单位窗口内被触及的不同 Ticket 数(即上下文切换次数);
- 人被占用的墙钟时长。

### 4.4 为什么必须联合:四个耦合

这是 A 这条切法成立与否的关键。拆开优化任一项都会失真:

1. **槽位耦合**〔一手〕。Ticket 从 launch 起持续占槽;准入一个低价值候选会推迟一个高价值候选的启动。**准入与调度不可分离。**
2. **队列耦合**〔一手〕。所有 Ticket 的交接落在同一个人的队列上;对 A 的呈现决策改变 B 的交接延迟。而 host 侧无人类饱和概念,**这个耦合当前完全没有被建模**。
3. **疲劳反馈环**〔二手〕。呈现更多 → 负载更高 → 审查质量更低 → 结果更差。所以呈现量与实现价值之间**不是单调关系**;一个被草率审过却合入的 PR 是负价值。
4. **探索耦合**〔一手〕。准入策略决定了哪些规则会产生结果数据(§2.1)。因此准入不只是当期取舍,还决定了**另外两个决策未来可用的证据**。

第 4 条在已有文献里基本没有对应物,因为按实例的 defer 问题不存在"我的决策改变了未来数据集"这一层。

### 4.5 槽位不是常数:把 DSec 的发现并进来

〔站内〕以下 DSec 事实来自本站 dispatch 46 与 `data/agentic.json` 的卡片(带页码引用),**本会话未读 DSec 原文**(arxiv 被拦)。该卡片的站内可信度标为 **`self-reported`**——DeepSeek 自己的报告,实验平台是 AMD EPYC 9655 与 NVIDIA MIG,非昇腾。

§4.1 把 worker 槽建成一个固定整数 $W$,那是照 dsh 的 `maxWorkers` 来的〔一手〕。但 dsh 这个参数**把两件事混成了一件**:

- 有多少 Ticket 可以**持有可恢复状态**(存在于"工作中"的某一档);
- 有多少 Ticket 可以**此刻正在跑一个回合**,独占算力。

一手证据就在机制里:Ticket **从 launch(含 preparation)起、在每个活跃回合中持续占槽**;若回合结束时还有后台作业,Ticket **保留其槽并停在 Working**;后台工作每回合后给 **30 分钟**,到点杀掉 shell job 并把 Ticket 报为 waiting〔全部一手〕。那个 30 分钟超时,就是一个**粗糙的回收代用品**。

DSec 的整篇论文正是针对这个现象,其卡片标题直接写着把**"环境长期存在"与"资源长期独占"拆开**〔站内〕。支撑它的观测与 ABO 高度相关:

| DSec 观测〔站内·self-reported〕 | 对 ABO 的含义 |
|---|---|
| 约 90% 的沙箱平均 CPU 不超过申请额度的 5% | 长期存活但闲置是**主流情形**,不是边角 |
| 生命周期中位数 container 17.4 分钟、microVM 15.5 分钟,**p99 为 231.5 / 213.9 分钟** | 重尾。一个"waiting for a Trigger"挂几天的 Ticket 正是 p99 那一端 |
| 区分 latency-sensitive 与 best-effort,BE 走 SCHED_IDLE + core scheduling | 正好对应 ABO:**人正在等的交接是 LS,投机性后台工作是 BE** |
| DAMON + free-page reporting 回收冷页;virtio-pmem + DAX 去重文件缓存 | 回收**不必摧毁状态**,这正是 30 分钟超时做不到的事 |

**所以 §4.1 的 $W$ 应当拆成两个约束**〔设计〕:

- $W_{\text{res}}$:**状态驻留容量**——多少 Ticket 能持有可恢复状态;
- $W_{\text{exec}}$:**活跃执行容量**——多少 Ticket 能此刻跑一个回合。

有回收时 $W_{\text{res}} \gg W_{\text{exec}}$;没有回收时(今天的 dsh)两者被迫相等。

### 4.6 这件事对本提案是双向的,必须如实记

**加强的一面**:若 $W_{\text{res}}$ 可以做得很大,agent 侧约束就松了,**人类注意力更加独占瓶颈地位**——正是 §1 的命题。

**削弱的一面,而且必须写在前面**:§4.4 第 1 条耦合(槽位耦合:准入一个低价值候选会推迟一个高价值候选)**整个建立在槽位稀缺之上**。如果回收让驻留变便宜,这条耦合就变弱,而第 2/3/4 条(人类队列、疲劳反馈、探索)完全不受影响。

即:**DSec 在加强本提案总命题的同时,削弱了四条耦合里最弱的那一条。** 这不是要回避的尴尬,它反而让 M4(§10)的消融变得有判定力——

> **固定 $W$ vs 弹性 $(W_{\text{res}}, W_{\text{exec}})$ 的消融,直接回答"槽位耦合到底值不值一条"。** 若前沿在两种设定下几乎不动,就应当把 §4.4 砍成三条耦合并照实说明,而不是留着一条靠稀缺假设撑起来的论证。

**三条不能越界的限定**〔站内,均为本站对 DSec 的既有告诫〕:

1. **"90% 不超过 5%" 不是可以无条件超配 20 倍的证明**——并发测试与编译峰值可能相关;
2. **"单作业可突发 32K 沙箱"是突发创建需求**,不是必须同时运行 32K 个;
3. DSec 把 worker 与 agent sandbox **移出可抢占 GPU 池**,是为避免"环境还在、控制进度丢失",这**不自动覆盖**任意节点断电、网络分区或外部副作用。

对 ABO 的实际做法:模拟器把 $W_{\text{res}}$ 与 $W_{\text{exec}}$ 作为两个独立参数扫,**不去实现 DSec 的任何机制**。本提案不做系统实现,只问"驻留容量放宽后,注意力前沿是否移动"。

## 5. 可审计性:一条把方法空间削窄的硬约束

`docs/002-authorization.md`〔一手〕:Mandate 记录其被接受时的**规则集与 Policy 版本**;改变 Mandate 只有三种途径(accept 创建、人的 stop 撤回、revalidation 失败吊销);Policy 版本 = 规则 + 接受模式 + 各 Source 的 Policy,版本变更会丢弃进行中的 Eval 并重新入队。

含义:**策略必须能被人逐条读、逐条吊销、并与一个版本号绑定。黑箱神经门控在这套架构里不可部署。** 这不是我额外施加的审美约束,而是目标系统的既有要求,它直接决定了 §7 的策略类。

同一文档第一句给出注入不变量:**"host 强制执行允许名单、规则与 Mandate。消息、评论与被引用的文档是决策的输入,它们不能改变这些权限。"** 并补充:Executor 不能声称某人要求它停止。

## 6. 与相关工作的边界

> 本节除标注〔一手〕处外**全部为二手摘要**,编号与结论均待核(§12)。

| 工作 | 它做了什么 | 与 ABO 的差别 |
|---|---|---|

### 6.2 真正剩下的空缺(2026-11-06 读完 2402.12237 全文后重写)

读全文后结论比只读摘要时**明确得多,且对本提案有利**。Lykouris & Weng 的人类模型由三条他们自己写明的假设钉死,而**agent 把关恰恰是这三条都不成立的场景**:

| 他们的假设(全文原文) | 位置 | 对本提案的含义 |
|---|---|---|
| "Although the above line of work as well as ours **assumes perfect labels from human predictions**" | §1.3 相关工作 | 人类标签完美,**不会错** |
| "**all jobs eventually reviewed by humans incur zero loss**" | Remark 1 | 复核过即零损失;Remark 1 讨论的扩展是**等待时间的 holding cost,不是人会出错** |
| "we do assume that the arrival probabilities and **reviewer capacities are exogenous**, i.e., this is an oblivious adversary setting" | §2 模型 | **容量外生**:策略自己的负载不改变容量 |

并且 **`fatigue` 一词在全文 98 页中出现 0 次**;`switching cost`、`context switch`、`human error` 同样为 0〔一手·全文检索〕。

于是剩下的空缺不再是"组合式增量",而是**他们模型的构造性前提在本场景下失效**:

1. **容量内生(最硬的一条,且是真正的技术难点)。** 他们的 regret 定义建立在 (Fluid) 基准上,而该基准**以外生容量为前提**构造。若容量随策略自身的负载变化(呈现越多 → 人越饱和 → 有效容量越低),**基准本身会随策略移动**,"对固定 fluid 基准的 regret"就不再良定义。这不是把两篇拼起来,而是他们分析框架的前提被破坏后要重建。2606.08919 已用仿真表明这会让实现安全性对 escalation rate 呈**倒 U**——即最优准入规则对负载的响应**变号**:他们的世界里多准入只增加延迟(单调),有疲劳的世界里多准入可能降低质量(非单调)。
2. **人类会错,且错误率随负载上升。** 直接违反上表前两条。复核不再等于"零损失",于是"把作业送去复核"不再是无风险的止损动作。
3. **Ticket 不是 job。** 他们的作业被成功复核**一次**即终结(复核失败只是重入队列等待再次服务,属服务时间模型,不是新的交互);而 Ticket〔一手〕跨多回合持槽,在 `ready`、提问、`blocked`、`failed` 及后续人类消息处**反复触达同一个人,每次携带不同信息**,且人的回答会改变 agent 下一步做什么。他们的模型表达不了"同一个 Ticket 第三次来问你"。
4. **可审计性 + 注入不变量作为策略类约束(§5、§7.2)。** 四篇前作都没有。来自 dsh 的真实架构要求,使策略只能取可读的索引形式,并让注入不变量**在构造上成立且可机械判定**。
5. **驻留容量 vs 执行容量的二分(§4.5)**;以及**真实 GitHub 事件流重放 + 注意力账本的 benchmark(§8)**——他们用的是 Wikipedia 与 Civil Comments 评论数据的**仿真实验**,agentic/仓库版本无人做。

> **一句话定位(替代被推翻的 §1):Lykouris & Weng 在"人类是完美且外生的 oracle"前提下解决了准入+调度+学习;而 agent 把关正是人类既不完美、也不外生的场景。**

### 6.3 补读附录(2026-11-06):外生性依赖有多深,以及第一个定理该长什么样

§6.2 把"容量内生破坏其基准构造"列为技术核心,但那时只读了正文。补读 Appendix D 与 E 后,这一判断**得到他们自己文本的支持,并且第一个定理有了现成模板**。

**(a) 基准里 N(t) 是数据,不是变量。** Appendix E 的 w-fluid 基准定义为

$$L^\star(w,T) := \min_{\tau,\{a_k(t)\},\{\nu_k(t)\}} \sum_t \sum_k \ell_k(\lambda_k(t)-a_k(t)) \quad \text{s.t.}\quad \sum_{t \in \text{window}} a_k(t) \le \mu_k \sum_{t \in \text{window}} N(t)\nu_k(t)$$

**容量序列 $N(t)$ 出现在约束右端,基准在给定 $N(t)$ 的条件下对准入与服务分配取最小。** 若 $N(t)=N(t;\pi)$,可行集随策略变化,$L^\star$ 不再是一个数而是 $L^\star(\pi)$,于是 $\mathrm{Reg}=\mathbb{E}[L^\pi]-L^\star(\pi)$ 是**拿策略去比一个被它自己挪动过的基准**——一个策略可以靠把人累垮、同时把基准也拉低来"显得不差"。这是定义层面的退化,不是精度问题。

**(b) 连外生的非平稳情形,他们都说基准未解决。** Appendix E 开篇:"**Extending the fluid benchmark to a non-stationary setting is non-trivial**";其 open directions 更直接:"**Identifying a suitable benchmark for a non-stationary queueing system remains an open question**"。注意这是**容量外生但随时间变化**的情形——内生严格更难。

**(c) 他们已经碰过一次"基准忽略真实成本"的困境,并证明了后果。** Appendix D 给 holding cost(等待期间的损失)。**Proposition 2**:在单类型平稳设定下($N(t)\equiv 1$,$\lambda_1=\mu_1=\ell_1=0.5$,$h_1(0)=0,h_1(d)=1\ \forall d\ge1$),**任何策略的 holding-adjusted regret 都 $\ge 0.25T$**,即线性。因为基准完全忽略 holding cost,"次线性 regret"这个目标本身变得不可达。

**(d) 他们的解法不能照搬到内生容量上——这正是空缺所在。** 他们的出路是**限制成本类**:要求边际 holding cost 随时域消失($h_k(d+1)-h_k(d)\le T^{-\omega}$),于是 OLBACID 重新取得次线性 regret(Proposition 3)。把同样手法用到疲劳上,等价于假设**单位负载造成的容量退化随 $T\to\infty$ 消失**——那就等于把要研究的现象本身假设掉了。**会疲劳而疲劳效应随时域消失的审查者,不是会疲劳的审查者。**

**(e) 于是第一个定理有了模板。** 照 Proposition 2 的结构:

> **待证命题(路线甲的第一步):** 在容量内生($N$ 随策略近期呈现负载单调不增)且退化不随 $T$ 消失的设定下,**对 (Fluid) 与 w-fluid 基准的 regret 对任何策略都是线性的**;因此需要一个新的、良定义的基准。

**试证结果(2026-11-06 两轮),见配套笔记 `abo-endogenous-capacity-note.md`:⛔ 路线甲被否,已转路线乙。**

- **定理 A 已证**:在单类型平稳实例($\lambda\equiv1$、名义 $\mu\bar N=1$)与最简疲劳模型下,**任何**策略对按名义容量算出的 (Fluid)/w-fluid 基准的 regret $\ge\frac{\ell\delta}{2}T$,即线性。结构与原文 Proposition 2 完全平行。
- **但定理 A 有廉价修补**:把基准容量换成可持续速率即可恢复次线性。**故它只证明了"朴素基准无效",没有证明"没有任何 fluid 基准可用"**。
- **命题 B 已证**:存在两个**每窗口质量完全相同**但真实可实现吞吐相差 $\delta$ 的服务排布(4 期、2 窗口),故**任何外生容量序列都无法精确表示真实可行集**——根因是 $w$-fluid 跨窗口无记忆,而疲劳是跨窗口状态。
- **⛔ 命题 C 已否定路线甲**:取可持续速率 $r^\star=1/(1+\delta)$ 的 fluid 基准与真实最优值只差 $O(1)$(解析论证 + 对疲劳状态精确 DP 的数值确认,稳态与非稳态压满实例均如此)。**漏洞在于「可行集无法精确表示 ⇒ 基准值无法逼近」的第二步不成立**:fluid 基准只需在最优值上对齐,不需要在可行集上对齐,而命题 B 的 A/A' 差异发生在最优解不会选择的排布之间。
- **据此触发 §12.1 预案,转路线乙(benchmark 优先)。** 定理 A 降级为一条 remark:别用名义容量,用可持续速率。
- 引理与反例已由 `abo-bench/theory/verify_endogenous_capacity.py` 机械核验(暴力枚举全部排布)。

## 7. 算法设计

### 7.1 策略类:按流索引 + 可读特征

由 §5 的可审计约束,策略取**按流索引评分**形式:每个候选/Ticket 得一个索引值,在共享注意力预算下按索引排序。索引对特征**线性或单调**,使每一项贡献可归因、可逐条吊销、可与 Policy 版本绑定。

选索引策略而非端到端黑箱的理由有两层:可审计性(§5),以及共享预算下的多流分配天然适合索引式分解(此为从受限资源分配文献的**引入**,未发现 LLM agent 场景的既有应用〔二手〕)。

### 7.2 Trusted-only 特征集:让注入不变量在构造上成立

索引**只允许**取 host 从可信状态计算的量:

- 命中规则的身份与条数、sender 的允许名单成员资格与 admission 强度、Policy 版本;
- 队列深度、槽位占用、Thread/Ticket 年龄、近期注意力消耗;
- 该规则的历史结果统计。

**显式排除**:任何由未受信的消息正文 / 评论 / 被引用文档计算出的量。

这样 §5 那条不变量对**权限与调度决策** by construction 成立——Executor 仍可为完成任务去读未受信内容,但读到的东西无法移动它自己的优先级或权限。**并且这一条是可测的**:构造对抗注入测试集(文本试图抬高自身优先级或声称获得授权),不变量成立当且仅当索引值逐比特不变。

这把一个通常靠过滤与对齐处理的问题,变成了**策略类的结构性质**。

### 7.3 训练

1. **模拟器内约束 RL**:以拉格朗日对偶处理注意力预算,扫 $B$ 得前沿。**此处无方法创新**——FALCON(2604.00904)已是 CMDP + PPO-Lagrangian + 协作预算〔一手·摘要〕,本提案沿用其做法,差别只在决策集与人类模型;
2. **影子日志离线评估**:`observe` 模式记录的 `"would accept"` 恰好是一份影子日志〔一手〕。以 HarnessMDP 的"离线 rollout + AWR"为方法模板〔二手〕,但须正面处理它们自己指出的局限——离线支撑集限制了流程控制改善何时能转化为终局改善〔二手〕;
3. **呈现子策略**:带切换成本的批处理窗口与优先序。与现状对照明确——替代 panel 那个 24 小时阈值〔一手〕。

## 8. ABO-Bench

### 8.1 为什么用真实事件流重放

公开 GitHub 事件流(issue / PR / review comment / CI 结果)可重放,**而且维护者的真实响应延迟与动作就在 trace 里**:谁在什么时候回复、什么被合入、什么被关闭、隔多久。于是人类响应模型**从真实数据标定**,而非合成。

这正面补上 DeepSeek 自评的弱点(合成负载、以消耗时间的工具模拟写代码)〔二手〕。

### 8.2 构成

- **难度三档**:单仓库低流量 / 单仓库高流量 / 单操作者多仓库;
- **价值定义**:可归因的解决(agent 接受的工作产出的 PR 被合入 / issue 被关闭),反事实基线取 trace 中历史上实际发生了什么、耗时多久;
- **注意力账本**:§4.3 的五项可数单位;
- **对抗注入套件**:§7.2 的不变量测试;
- **诚实的局限**(写入 benchmark 文档,不藏在附录):
  - 从未执行的动作**没有结果标签**,重放只能给部分 ground truth(例如"这活后来人自己做了");
  - 价值归因是代理指标;
  - 切换成本的权重最终需要人类研究标定,trace 推不出"一次打扰值多少"。

## 11. 最小可行实验与成功判据

**最小实验**:单仓库、一个月真实事件流、槽位 $W \in \{1,3,5\}$,比四条策略的价值—注意力前沿:learned index / 手写阈值 / 全问 / 全自动。

**刻意不含**弹性槽位:$ (W_{\text{res}}, W_{\text{exec}}) $ 的拆分属于 M4 消融(§4.6),不进杀死测试。杀死测试要回答的是"有没有东西可优化",多加一个维度只会让它更慢、更难解读。

**成功判据**:在**相同注意力预算下交付价值显著更高**,或**相同价值下注意力显著更低**;且前沿在 $W$ 变化时不交叉(即结论对并发度稳健)。

**失败判据(同等重要)**:若 learned 策略压不过手写阈值,则"联合优化有收益"这一命题为假,应尽早转向 §12.1 的退路。
