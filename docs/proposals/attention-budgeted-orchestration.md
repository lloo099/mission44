## 1. 一句话定位

主动式 agent 系统里,**人类注意力是被 N 条并发工作流争抢的、有限且会排队的资源**;本项目把准入(接不接这件事)、调度(谁占 worker 槽)、呈现(什么现在送到人面前)当作**一个**联合资源分配问题来形式化、测量和学习,替代目前全靠手写提示词与魔法数字的做法。

---

## 2. 问题陈述:三个可指认的病灶

主动式 agent 每天反复做同一个判断:**现在就做 / 问人一句 / 先不出声**。这个判断今天由手写规则加一个三档开关决定,而**没有任何指标能衡量写得对不对**。`dsh-superagent` 把机制完整公开,于是病灶可以被精确指认(以下均〔一手〕):

### 2.1 出厂默认档位是"永远不行动",且不产生学习信号

`docs/002-authorization.md`:接受模式有 `off` / `observe` / `auto` 三档,**`observe` 是默认**。该档下推断候选照常评估,正向评估被**记录为 ignore 并标注 `"would accept"`,不接受任何工作**。文档要求"从 `observe` 起步,复核记录下来的 Decision 之后再切到 `auto`"。

但文档**没有给出任何判据说明什么时候算复核够了**。后果有两层:

1. 交付层面:留在 `observe` 则主动能力产出恒为零;
2. **信息层面:`observe` 下动作从未执行,因此被评估的规则永远不产生结果标签**。出厂默认配置**在构造上就是信息饥饿的**——它既不交付价值,也不积累能用来改进自己的证据。

### 2.2 槽位限制约束的是 agent 并发,没有任何机制约束人类负载

`docs/007-architecture.md` 给出并发表:`assessment` 4、`delivery` 4、`relay`/`notice`/`reply` 各 1、`launch` 为空闲 worker 槽数;`WorkerSlots` 在 launch 或 wake 前预留容量,**一条人类消息可以多占一个槽超出 `maxWorkers`,且 wake 优先于 launch**。`docs/003-execution.md`:一个 Ticket **从 launch(含 preparation)起、在每个活跃回合中持续占用一个 worker 槽**。

而交接规则是:Ticket 在 `ready` Report 或提问后交给人(除非有新 Input 到达),任何 `blocked` / `failed` Report 之后也交给人。

两者合起来意味着:**5 个 Ticket 同时完工就是 5 个交接同时到达同一个人**。槽位机制精确地限制了 agent 侧并发,但 host 侧**不存在"这个人当前已饱和"这一概念**,人类负载没有任何节流。

### 2.3 呈现规则是未经测量的魔法数字

`docs/002-authorization.md`:panel 只在 Decision 为 `unavailable`、**年龄小于 24 小时**、是其 Thread 上最新、未被 dismiss、且 Thread 既不在排队也不在评估时,才请求人类注意力。`evals` 健康项报告**最近一小时**未解决的 unavailable Decision。

24 小时与 1 小时这两个阈值没有任何测量支撑。它们是合理的工程直觉,但正是"无法判断自己写得对不对"的典型样本。

> 补充一条机制性风险,与本提案目标直接相关〔一手〕:`docs/007-architecture.md` 明确"目前没有任何机制删除旧记录,因此多数表无界增长"。长期运行下,注意力相关的历史统计本身会变成成本。

## 3. 时机:为什么现在做

三条同时成立,构成一个窄窗口:

1. **机制第一次可读可改**〔一手〕。`dsh-superagent` 以 MIT 发布,把准入模式、Mandate 与 Policy 版本、槽位与并发、Ticket 七档 stage、panel 注意力规则全部写成文档。这类系统此前只存在于各家内部,研究者无法指认其决策点。
2. **目标函数已被写下,但从未被优化**。`docs/000-philosophy.md` 的原则是 **"Take as little human attention as possible, and give as much value as possible"**,并明确衡量标准是"一条消息消耗的注意力 vs 它交付的价值,**而不是 agent 完成了多少工作**",还给出"the right help at the right time, and nothing at any other time"〔一手〕。而按二手报道,配套设计文章《Exploring Super-agent Design: Towards a More Autonomous Agent System》(约 2026-10-31)称**一个人通常只能盯 3–5 个并发 agent 会话**,其实验为**合成负载、以"消耗时间的工具"模拟写代码**,只测调度与协调而非代码质量,报告中位完成时间比 neutral-prompt 基线低 **39.2%**、cache 读约 3.8 倍〔二手,数字待核〕。

   这组事实的含义很具体:**一句提示词就拿到 39.2%,说明这个杠杆有效且几乎未被开发,而他们自己的评测承认是合成的。**
3. **文献三面包夹,中间是空的**。见 §6。

## 4. 形式化:ABO

### 4.1 决策变量

离散时间。外部事件流(GitHub 事件 → Trigger)到达,router 在每一步面对三类决策:

| 决策 | 动作空间 | 对应的真实机制〔一手〕 |
|---|---|---|
| **准入** $a^{\text{adm}}$ | {拒绝, 仅记录, 接受} | Eval → Decision → accept 创建 Ticket/Mandate/Assignment |
| **调度** $a^{\text{sch}}$ | 启动顺序、wake 与 launch 的优先、是否让位 | `WorkerSlots`、`maxWorkers`、wake 优先于 launch |
| **呈现** $a^{\text{sur}}$ | {立即送, 并入下一批, 延后, 暂不送} × 粒度(摘要/全量 diff) | Ticket stage 决定"谁该管"、panel 的注意力规则 |

### 4.2 人类模型(本提案的核心建模对象)

把操作者建成**单服务器排队系统**,四个要素:

1. **有限服务率** $\mu$(件/小时);
2. **切换成本** $s$:相邻处理的两件事属于不同 Ticket 时产生。按二手的实践观察,切换的代价主要不在切换动作本身,而在**重新装载该任务历史与先前决策的恢复时间**〔二手〕;
3. **质量随负载退化** $q(\ell)$:审查准确率随瞬时负载 $\ell$ 下降。这一项是"呈现更多不等于更安全"的来源〔二手,且为建模结论,见 §12〕;
4. **可用窗口**:从 trace 中维护者的真实活跃时段估计,不假设人随时在线。

### 4.3 目标

$$\max\ \mathbb{E}\Big[\textstyle\sum_t \text{value}_t\Big] \quad \text{s.t.}\quad \text{注意力消耗率} \le B$$

**但主结果不报单一数字,而是扫 $B$ 得到的价值—注意力前沿。** 理由直接来自 philosophy 文档:最优工作点依操作者而异,"值不值得打扰"本身是操作者的偏好〔一手〕。注意力按**可数单位**计量,不引入主观评分:

- 需要人处理的条目数;
- 送达的通知数;
- 人必须读的 review 量(diff 行数 / token);
- 单位窗口内被触及的不同 Ticket 数(即上下文切换次数);
- 人被占用的墙钟时长。

### 4.4 为什么必须联合:四个耦合

这是 A 这条切法成立与否的关键。拆开优化任一项都会失真:

1. **槽位耦合**〔一手〕。Ticket 从 launch 起持续占槽;准入一个低价值候选会推迟一个高价值候选的启动。**准入与调度不可分离。**
2. **队列耦合**〔一手〕。所有 Ticket 的交接落在同一个人的队列上;对 A 的呈现决策改变 B 的交接延迟。而 host 侧无人类饱和概念,**这个耦合当前完全没有被建模**。
3. **疲劳反馈环**〔二手〕。呈现更多 → 负载更高 → 审查质量更低 → 结果更差。所以呈现量与实现价值之间**不是单调关系**;一个被草率审过却合入的 PR 是负价值。
4. **探索耦合**〔一手〕。准入策略决定了哪些规则会产生结果数据(§2.1)。因此准入不只是当期取舍,还决定了**另外两个决策未来可用的证据**。

第 4 条在已有文献里基本没有对应物,因为按实例的 defer 问题不存在"我的决策改变了未来数据集"这一层。

## 5. 可审计性:一条把方法空间削窄的硬约束

`docs/002-authorization.md`〔一手〕:Mandate 记录其被接受时的**规则集与 Policy 版本**;改变 Mandate 只有三种途径(accept 创建、人的 stop 撤回、revalidation 失败吊销);Policy 版本 = 规则 + 接受模式 + 各 Source 的 Policy,版本变更会丢弃进行中的 Eval 并重新入队。

含义:**策略必须能被人逐条读、逐条吊销、并与一个版本号绑定。黑箱神经门控在这套架构里不可部署。** 这不是我额外施加的审美约束,而是目标系统的既有要求,它直接决定了 §7 的策略类。

同一文档第一句给出注入不变量:**"host 强制执行允许名单、规则与 Mandate。消息、评论与被引用的文档是决策的输入,它们不能改变这些权限。"** 并补充:Executor 不能声称某人要求它停止。

## 6. 与相关工作的边界

> 本节除标注〔一手〕处外**全部为二手摘要**,编号与结论均待核(§12)。

| 工作 | 它做了什么 | 与 ABO 的差别 |
|---|---|---|
| **HarnessMDP**(arXiv 2607.05458) | 把 harness 当可学习控制层,形式化为有限时域 Harness MDP;轻量 controller 选择结构性执行动作,LLM executor 冻结;**从离线 rollout 以 advantage-weighted regression 训练**,只用终局 rubric 奖励 | **决策集完全不同**:它管的是**单任务内**的流程动作(何时 read / draft / verify / revise / retrieve / submit),模型里**没有人类、没有并发、没有准入**。对本提案是**方法先例**(证明 harness 控制可离线学),不是竞争 |
| **SPOQ**(arXiv 2606.03115) | 多 agent 软件工程的排队编排;有"Director Model",一名工程师驱动多个 Claude Code 实例,称约 6 个并发是人类多任务的经验上限 | **明确把训练与上下文切换成本排除在其成本模型之外**。这正是 ABO 要建模的量——最接近的系统论文把它划出了范围 |
| **Oversight Has a Capacity**(arXiv 2606.08919) | 把 escalation 当**预算问题**;审查者建模为随 escalation 负载疲劳;得到 realized safety 对 escalation rate 呈**倒 U**,安全最优护栏的 escalation 低于全量,且 load-aware 策略能抗 flooding | **最接近的前作,也是最大的 novelty 威胁。** 差别:它管**安全护栏该拦哪些动作**(分类 + 预算),不管**准入与跨流调度**;策略是校准出来的而非学出来的;且倒 U 与 flooding 按 arXiv 摘要是**建模结论,用于 motivate 未来的人类研究**〔待核,见 §12〕 |
| **按实例 defer 一族**:HILA(2603.07972, ICLR 2026,GRPO + cost-aware reward 决定自做还是交专家)、ASK-L2D(2605.24350,按打断成本与误动作成本之比设阈值)、When2Ask(RLC 2024,计入 API 费用与延迟)、FALCON / To Ask or Not to Ask(2510.08314,把疲劳建成约束) | 学"这一道题要不要问人" | **单流、按实例、人是成本固定或疲劳的 oracle**。无法表达"问 A、把 B 与 C 并批、D 等人空了再说"——那需要把注意力当共享队列 |
| **agent 系统优化一族**:ADAS(ICLR 2025,搜索空间是代码)、AFlow(MCTS over LLM 节点图)、GEPA(提示词优化)、EvoFlow、AgentFactory(2609.01045)、HarnessForge(2606.01779) | 搜索提示词与工作流结构 | **目标函数是任务准确率**,没有人类注意力项,没有并发资源约束。是本提案的 baseline 而非前作 |
| **AI control**(Redwood 一族) | 有**人类审计预算**(低至约 1/10,000 动作),研究预算下的监控协议 | 预算花在**防模型故意颠覆**,不是花在产出价值。目标函数与威胁模型都不同 |
| **Horvitz et al., Attention-Sensitive Alerting**(UAI 1999) | 把通知当决策问题:延迟告警的成本 vs 打断成本;贝叶斯推断用户注意力焦点 | **思想祖先**。但无多源共享预算、无并发工作流、非 agent 场景,也不含学习 |
| **主动性 benchmark**:ProEvent(2607.17701,即时通讯对话,评响应时机/单步正确/多步成功)、Proactive Eval(沉默/短消息/带动作消息三选一) | 评"该不该出声" | 单轮或单流打分,**不含并发、不含注意力预算、不重放真实事件流** |
| **人类监督一族**:OrchVis(2510.24937,supervisor 分解目标并把冲突交人)、Partitioned Human Supervision(2510.22500)、Human-LLM Collaborative Planning(2605.23023) | 系统与界面侧的监督组织 | 系统/交互贡献,不含资源分配的形式化与学习 |

**空缺的位置。** 搜索未找到任何工作把**单个人类审查者建成带切换成本的队列、并据此学习呈现策略**;也未找到把 **GitHub 事件流重放 + 注意力成本 + 并发**三者合一的 benchmark。实践侧的共识(agent 并行生成但人类评审与集成仍是串行的"编排税";评审队列变长就该降并发)只存在于从业者文章,没有形式化处理〔二手〕。

**因此 ABO 的位置是:不问"该不该问人",而问"自主权与注意力如何在并发工作流之间分配"。**

## 7. 算法设计

### 7.1 策略类:按流索引 + 可读特征

由 §5 的可审计约束,策略取**按流索引评分**形式:每个候选/Ticket 得一个索引值,在共享注意力预算下按索引排序。索引对特征**线性或单调**,使每一项贡献可归因、可逐条吊销、可与 Policy 版本绑定。

选索引策略而非端到端黑箱的理由有两层:可审计性(§5),以及共享预算下的多流分配天然适合索引式分解(此为从受限资源分配文献的**引入**,未发现 LLM agent 场景的既有应用〔二手〕)。

### 7.2 Trusted-only 特征集:让注入不变量在构造上成立

索引**只允许**取 host 从可信状态计算的量:

- 命中规则的身份与条数、sender 的允许名单成员资格与 admission 强度、Policy 版本;
- 队列深度、槽位占用、Thread/Ticket 年龄、近期注意力消耗;
- 该规则的历史结果统计。

**显式排除**:任何由未受信的消息正文 / 评论 / 被引用文档计算出的量。

这样 §5 那条不变量对**权限与调度决策** by construction 成立——Executor 仍可为完成任务去读未受信内容,但读到的东西无法移动它自己的优先级或权限。**并且这一条是可测的**:构造对抗注入测试集(文本试图抬高自身优先级或声称获得授权),不变量成立当且仅当索引值逐比特不变。

这把一个通常靠过滤与对齐处理的问题,变成了**策略类的结构性质**。

### 7.3 训练

1. **模拟器内约束 RL**:以拉格朗日对偶处理注意力预算,扫 $B$ 得前沿;
2. **影子日志离线评估**:`observe` 模式记录的 `"would accept"` 恰好是一份影子日志〔一手〕。以 HarnessMDP 的"离线 rollout + AWR"为方法模板〔二手〕,但须正面处理它们自己指出的局限——离线支撑集限制了流程控制改善何时能转化为终局改善〔二手〕;
3. **呈现子策略**:带切换成本的批处理窗口与优先序。与现状对照明确——替代 panel 那个 24 小时阈值〔一手〕。

## 8. ABO-Bench

### 8.1 为什么用真实事件流重放

公开 GitHub 事件流(issue / PR / review comment / CI 结果)可重放,**而且维护者的真实响应延迟与动作就在 trace 里**:谁在什么时候回复、什么被合入、什么被关闭、隔多久。于是人类响应模型**从真实数据标定**,而非合成。

这正面补上 DeepSeek 自评的弱点(合成负载、以消耗时间的工具模拟写代码)〔二手〕。

### 8.2 构成

- **难度三档**:单仓库低流量 / 单仓库高流量 / 单操作者多仓库;
- **价值定义**:可归因的解决(agent 接受的工作产出的 PR 被合入 / issue 被关闭),反事实基线取 trace 中历史上实际发生了什么、耗时多久;
- **注意力账本**:§4.3 的五项可数单位;
- **对抗注入套件**:§7.2 的不变量测试;
- **诚实的局限**(写入 benchmark 文档,不藏在附录):
  - 从未执行的动作**没有结果标签**,重放只能给部分 ground truth(例如"这活后来人自己做了");
  - 价值归因是代理指标;
  - 切换成本的权重最终需要人类研究标定,trace 推不出"一次打扰值多少"。

## 11. 最小可行实验与成功判据

**最小实验**:单仓库、一个月真实事件流、槽位 $W \in \{1,3,5\}$,比四条策略的价值—注意力前沿:learned index / 手写阈值 / 全问 / 全自动。

**成功判据**:在**相同注意力预算下交付价值显著更高**,或**相同价值下注意力显著更低**;且前沿在 $W$ 变化时不交叉(即结论对并发度稳健)。

**失败判据(同等重要)**:若 learned 策略压不过手写阈值,则"联合优化有收益"这一命题为假,应尽早转向 §12.1 的退路。
