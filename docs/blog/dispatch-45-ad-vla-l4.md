# Dispatch 45 · 车上的大模型与 L4:带宽、语言与可认证性,三堵墙各是什么性质

*2026-10-07 · NPU Frontier Dispatch · autonomous-driving / VLA / on-device-inference / verification / RL-on-NPU*

> **TL;DR** — 读者问"把 LLM 部署到车上能不能做到 L4、甚至 L5"。六路调研加一轮对抗核验的结论比预期干脆:**L4 可达,而且已经被达到了——但不是靠车上的大模型**;**L5 不是工程进度问题,是定义问题**。三件事必须分开:离线 VLM(自动标注、难例挖掘、仿真)是语言今天真正创造价值的地方;车上**慢速分支**上的语义通道(Waymo 的两速架构)是语言可以待的地方;而**真正出控制量的,在每一个已出货的系统里都是非语言的轨迹头**。三堵墙性质不同:**带宽是工程问题,而且约束的形态与直觉相反**——在 273 GB/s 的车规带宽上,7B INT8 每做一次全权重读取要 36.6 ms,100 ms 控制周期里只够约 2.7 次**全权重读取**(不是 2.7 个 token——投机解码、多 token 预测与 MoE 都能让一次读取吐出多个 token);核验推翻了本站原先"出货模型恰好落在算术预测上"的说法——**实际出货的是 3–4B(理想 MindVLA 3.2B、小鹏车端 7B 量级),比朴素自回归的参数上限高 4 倍左右,厂商的解法不是把模型压小,而是把"每帧吐词"这件事从回路里工程掉**:小词表、投机推理、token 并行解码、MoE。**参数上限没有生效,token 预算生效了。** **语言这一层买到的驾驶能力,按作者自己的说法是持平而非增益**——SimLingo 纯视觉版 Driving Score **85.94**、带语言版 **85.07±0.95**,但核验查明这**不是受控消融**(epoch 30 对 14、编码器与语言解码器都换了、损失函数与数据组成都变了,且作者明说没在新设置下重跑基线);该论文唯一真正受控的语言开关(同权重、仅切换推理模式、3 个种子)**方向为正但不显著**:开思维链 85.07±0.95 / 67.27±2.11,关掉 84.41±1.76 / 64.84±2.42。Bench2Drive 闭环榜首确实是非语言策略(BridgeDrive 96.34、TFv6 95.28)、最好的 VLA 条目低 4.3–5.4 分,但同一榜页自述"比较的是整个方法,包括数据获取方式";**同一篇论文的 BridgeDrive 换一个专家数据就从 86.87 跳到 96.34(+9.47),接近语言/非语言差距的两倍**——所以这个差距至少同样可以由"谁用了最新的特权专家"解释。**可认证性才是结构墙**——ASIL-D 要求最坏执行时间有界,而自回归解码的 token 数数据相关、投机解码按构造让延迟随机;RAND 的 2.75 亿英里门槛对随机采样策略只会更难;UNECE 2026-06-24 通过的首个全球 ADS 法规走的是"安全论证 + 可信测试 + 在役监测"的过程路线,而非里程路线。产业的自答最有说服力,但要按核验后的口径说:**小鹏在第二代拆掉了"语言转译"这一段**(视觉→隐式 token→动作,<80 ms,官方框架是"语言是对物理世界的高度有损压缩")——注意这是**去掉解码为文本的通道,不是去掉语言**,车端仍是语言预训练的多模态 Transformer,监督仍由 72B 语言预训练云端模型蒸馏而来;**华为明确不走 VLA 路线**(IAS BU CEO 靳玉志 2025-08-28:VLA"看似取巧,其实并不是走向真正自动驾驶的路径",主张 WA 直接以视觉输入控车、"无需把各种各样的信息转成语言")——流传甚广的"VLA 太大太慢了"一句**本站核验后无法归属于靳玉志,已不作引用**;**Waymo 把 VLM 放在慢分支**,其 World Decoder 同时消费快慢两路并产出轨迹与校验信号,且官方确认"**一个独立而严格的车载校验层,用以验证由 Driver 的生成式 ML 模型产出的轨迹**"——但该校验层**本身也是学出来的**("独立的、基于 AI 的安全系统",作硬性兜底),不是规则检查器。而 Gemini 确实在 2026 年上了 Waymo 车——**在座舱里当乘客助手**。对本站:车端 NPU 与数据中心 NPU 的工具链基本是两个世界(地平线是 AOT、定形状、ONNX 进闭源 .hbm 出,连非 4D 输入都不支持),唯一的真收敛是华为——昇腾 610 与数据中心 910 共享达芬奇核与 CUBE 原语,而其云端训练路径本身就是 CANN + torch_npu 这套 LLM 栈。

## 1 · 读法:三件被混为一谈的事

几乎所有"车上跑大模型"的讨论都在混用三个完全不同的东西。先分开,后面每一节才有意义。

**① 离线 VLM。** 自动标注、难例挖掘、字幕与思维链生成、仿真素材。这是语言今天真正创造价值的地方——华为的云端世界引擎、Waymo 用 Gemini 训练的标注、NVIDIA Alpamayo 的 Chain-of-Causation 数据集("人在环的混合自动标注")。**它从不碰车**。

**② 车上的慢速语义分支。** Waymo 的架构是两速的:Sensor Fusion Encoder 在快反应路径上融合相机、激光与毫米波,Driving VLM 负责可容忍更高延迟的罕见语义推理。研究界把同一模式直接写进标题——"Think at 5 Hz, Act at 20 Hz"。**注意这里的措辞要准**:按 Waymo 自己的描述,快慢两路**都馈入产出轨迹的 World Decoder**,所以 VLM 是被移出**快反应路径**,不是被排除在控制路径之外(第 5 节详述本站在这一点上的更正)。

**③ 真正出控制量的策略。** 在每一个已出货的产品里,这都是**非语言的轨迹头**。特斯拉是"photons in → actions out",网络里没有语言模型;小鹏 VLA 2.0 是视觉→隐式 token→动作;理想把 32B 的 VL 基座蒸馏到 3.2B 的车端模型;华为叫"世界行动模型"而非语言模型;Momenta R6 是一段式端到端加 RL,没有语言阶段。**这一格里没有任何一个条目是在逐帧生成文本。**

## 2 · 带宽算术:被约束的不是模型有多大,是每帧能吐多少词

这一节是全篇最硬的部分,因为它是**算术,不是工程欠债**。

batch=1 的自回归解码每出一个 token,都要把全部权重从 DRAM 读一遍。每 token 时间有硬下界:

```
t_token = 参数量 × 每参数字节数 / 实际达到的带宽
```

车规 SoC 围绕 LPDDR5/5X 设计(受功耗、散热与 ASIL 约束),这个数就卡在 200–280 GB/s。带宽输入(每一项的档位已核过):**DRIVE Orin-X 204.8 GB/s(256-bit × 6400 MT/s LPDDR5);DRIVE AGX Thor 273 GB/s(256-bit × 8533 MT/s LPDDR5X)——注意这是开发者套件口径,NVIDIA 不公布车规量产 SKU 的带宽,"Thor-X"是中文市场简称而非 NVIDIA 型号;地平线 J6P 205 GB/s(<50 W,ASIL-D);蔚来 NX9031 546 GB/s(512-bit × 8533 MT/s 物理上成立,但来源是社交媒体帖,自报);特斯拉 AI4 约 384 GB/s(第三方拆解估算,特斯拉未公布)**。对照:发表过最好的驾驶 VLA 加速结果实际跑在 RTX PRO 6000 上,1792 GB/s、600 W——**是 Thor 带宽的 6.6 倍**;H100 SXM 3350 GB/s,12.3 倍。

控制周期按 10 Hz 即 100 ms 算,取 70% 的实际带宽利用率,在 **Thor(273 GB/s)** 上:

| 模型 | ms / 全权重读取 | 100 ms 内可做几次全权重读取 |
|---|---|---|
| 2.2B INT8 | 11.5 | 8.7 |
| 7B INT8 | 36.6 | **2.7** |
| 7B INT4 | 18.3(含分组量化元数据约 19.5) | 5.5 |
| 10B W4A8 | 26.2 | 3.8 |

**这张表的单位必须读准,否则会得出错误结论。** 本站核验时把自己原先的表述推翻了一次:这 2.7 **不是 2.7 个 token,而是 2.7 次全权重读取**。公式的前提是"每出一个 token 把全部权重读一遍",而这个前提恰好被这一领域正在用的技术击穿——**投机解码(用非自回归扩散草稿器)、多 token 预测、MoE 稀疏激活,都能让一次权重读取产出或验证多个 token**;MoE 尤其关键,它让带宽代价随**激活参数**而非总参数增长。FlashDrive 的加速正来自 8-token 块扩散投机草稿,约 10 个被接受的 token 只花约 1–2 次权重读取。所以这张表是**朴素稠密 batch-1 自回归解码的下界**,不是 token 数的上限。

另外两项不确定性要一并记上:**70% 是假设而非实测**——可查到的端点从 llama.cpp 在 Jetson AGX Orin 上约 1/3 的 roofline,到真正的 W4A16 Marlin 路径约 90%;按 33–90% 算,7B INT8 在 273 GB/s 上是 **28–78 ms**,即每 100 ms 1.3–3.5 次读取,而不是一个紧致的 2.7。车规 NPU 的 kernel 栈更靠近低端。而本表**没有计入 KV cache 的读取流量**——对一个有上千视觉 token 的多模态 VLA,这是真实的额外每 token DRAM 读取,**计入会更慢,所以这个方向上本表是保守的**。

<br>

**本站原先在这里有一个错误的论证,核验把它推翻了,改法如下。** 原先的写法是:把 40 ms 解码窗口除以"每帧 10 个 token",得到约 0.76B @INT8 的参数上限,再声称"已出货的系统恰好落在这条线上,吻合到 2 倍以内",并以此作为"这是真约束"的最强证据。这个论证有三处站不住:

1. **两个举例的对象都是错的。** 理想的 **2.2B 是上一代"端到端+VLM"架构里的 VLM 慢系统**,跑在第二颗 Orin-X 上、给另一个系统提建议,**它不出动作**;实际出货的 MindVLA 车端模型是 **3.2B**(从 32B 云端 VL 基座蒸馏,另有 3.6B 变体口径)。而 **FIVE-VLA(641M)根本没有上车**——它在 A100 上约 30 fps、T4 上约 4 fps,是研究模型,没有车、没有车规 SoC、没有量产项目。
2. **真实出货的规模高出上限约 4 倍,不是 2 倍。** 对 0.76B @INT8 这条线:MindVLA 3.2B 是 4.19 倍,小鹏车端约 3B 是 3.92 倍;即便按 INT4 的 1.53B 算也是 2 倍上下。而 DeepRoute 自报车端 40B、单步 60–85 ms、闭环 10–15 Hz——是上限的 52 倍,且与被本站采信的那些数字处在**同一个自报证据层级**。
3. **"每帧 10 个 token"是一个自由旋钮,所以这是事后拟合而不是预测。** 同一算术在 Thor 上从 7.64B(每帧 1 token)到 0.076B(每帧 100 token),跨度 100 倍;而没有任何厂商公布过每帧 token 数。反过来解:要让算术正好落在各家出货规模上,所需预算是 1.79(MindVLA 3.2B)、2.55(小鹏约 3B)、2.61(Orin-X 上的 2.2B VLM)——**旋钮不可观测,模型就能回溯任何数字,这个说法作为写法是不可证伪的**。

**核验留下的、本站现在采用的说法是这个,而且它比原来的更锋利:** 在车规 DRAM 预算上,**每帧生成冗长自然语言是负担不起的**——一个 100 ms 帧在 200–550 GB/s 的部件上,只够一个数十亿参数模型做个位数次全权重读取。这一点被一个很硬的事实从侧面证实:**每一家厂商公布的解法,都是"停止每帧吐词",而不是"把模型压小"**——小鹏拆掉语言转译层(视觉→隐式 token→动作,自报 <80 ms),FIVE-VLA 完全绕开文本生成,理想靠小词表加投机推理加 token 并行解码去换 >10 Hz,其明确的设计目标是"保证模型规模增长的同时,不降低端侧的推理效率"。**厂商并没有收敛到 0.76–1.53B,他们上了 3–4B,然后把 token 的吐出从回路里工程掉了。参数上限没有生效;token 预算生效了。**

**顺带把 TOPS 这个指标废掉。** 盈亏平衡算术强度 = 峰值 TOPS / 带宽。Thor-X 是 `1000e12 / 273e9 = 3663 ops/byte`,而 batch-1 的 INT8 GEMV 每读一字节权重只做 2 次运算。**解码用掉的是标称算力的 0.055%**(J6P 0.073%、Orin-X 0.161%)。车规营销里每一个 TOPS 头条描述的都是稠密卷积那种高算术强度的工况,**自回归语言解码从不进入那个区间**。更要紧的是,NVIDIA 的车规 TOPS 标的是 2:4 结构化稀疏——Jetson AGX Orin 的 275 稀疏 INT8 TOPS 对应 138 稠密,DRIVE Orin 的 254 同理;而 LLM 权重一般吃不了结构化稀疏,**可用的稠密值大约是头条的一半**。

把目前最好的公开结果搬到车规芯片上试算:FlashDrive(CoRL 2026)把 Alpamayo-1.5-10B 用 W4A8 加流式 KV 复用、块扩散投机解码、自适应动作缓存与 CUDA graph,从 717 ms 压到 **151 ms(1.4 Hz → 6.6 Hz)**——跑在一张 600 W 的工作站 GPU 上。按带宽折算解码、按稠密算力折算其余阶段,10B VLA 在 Thor 上约 **720 ms(约 1.4 Hz)**、Orin-X 上接近 2 s。**这个外推是本站做的,不是实测,而且两个方向上的误差不互相抵消**:非解码阶段用的是数据中心级的阶段耗时(偏乐观),解码阶段假设没有投机也没有 MoE(偏悲观);车规 NPU 也并没有 FlashDrive 所依赖的 Marlin / CUDA graph / vLLM 那套 kernel 栈。**按本站自己这组折算,Thor 上非解码阶段已达 424 ms——于是一个 100 ms 帧的解码预算是负的,这恰好说明上面那个"40 ms 解码窗口"是假设,不是推导。**

*图 4 · 便宜是怎么来的。原图出自 [hustvl/VAD](https://github.com/hustvl/VAD),**Apache-2.0**。VAD 的全部主张就是**把场景矢量化**——不用稠密栅格、不用占据体素,地图与他车都是少量 query 向量,于是推理代价塌了一个量级。把它和第 2 节的带宽算术放在一起看:**非语言策略之所以能在 100 ms 里从容跑完,是因为它的表示本身就是为这个预算设计的**;而自回归解码的代价结构与此正好相反——它的开销与"要说多少个词"成正比,而词数是数据相关的。这是第 8 节 WCET 那一节的技术前因。*

> **本站判断。** 带宽是**工程问题**,而且正在被解决——特斯拉 AI5 宣称 144 GB 与约 5 倍于 AI4 的带宽,蔚来 NX9031 宣称 546 GB/s。但真正值得记住的是**约束的形态**:它不约束模型有多大,它约束**每帧能吐多少词**。活下来的那个东西,已经不是在"说话"了。

## 3 · 语言这一层买到了什么:按作者自己的说法,是持平

这一节适用本站 D43/D44 反复用的那套方法学纪律,而且**反过来把本站自己也修了一次**——原稿的小节标题是"接近零",核验表明那个定性越过了证据能支撑的范围。

**最常被当作证据的对照是 SimLingo**(Wayve + 图宾根,CVPR'25 Spotlight),因为它同时放出纯视觉版与带语言版。数字本身经核验**全部对上**(论文表 2,专家列为 PDM-Lite):

| 配置 | Driving Score | Success Rate |
|---|---|---|
| SimLingo-Base / CarLLaVA(纯视觉,较小) | **85.94**(无误差棒) | 66.82 |
| SimLingo(完整 VLA,带 VQA / 解说 / 指令跟随) | **85.07 ± 0.95** | 67.27 ± 2.11 |
| 差值 | **−0.87** | +0.45 |

**但"这是最干净的受控消融"这个框架是错的,核验把它推翻了。** 论文自己的附录 B.3 列出了基线与完整版之间**至少四处同时发生的改动**:epoch 数 30 对 14;图像编码器 CLIP-ViT 对 InternViT-300M-448px;**语言解码器是 50M 的从零训练 LLaMA 架构 transformer,对 InternVL2-1B 的预训练 Qwen2-0.5B-Instruct 加 LoRA**(约 20 倍容量差,外加有无语言预训练之别);损失从 L2 改为 SmoothL1——而改损失的原因是加入 Action Dreaming 数据后训练不稳,**所以"同一数据"这一条也不成立**。论文并且明说没有在新设置下重跑基线:"由于 CARLA Leaderboard 关闭与算力开销,我们没有重复 SimLingo-BASE 的实验,我们相信相关论断与结果仍然成立。"一个同时移动了编码器、解码器架构、解码器规模、预训练、epoch 数、损失函数与数据组成的对比,**无法隔离"语言这一层"**。此外基线那一行**没有任何方差估计**(单次运行),所以 −0.87 甚至不能被称为"落在噪声内"——它是**无法被度量**。

**而论文里唯一真正受控的那个语言开关,方向与本站原稿相反。** 表 10(附录 C.3,同一组权重、只切换推理模式、3 个种子):**开思维链 85.07 ± 0.95 DS / 67.27 ± 2.11 SR,关掉思维链 84.41 ± 1.76 / 64.84 ± 2.42**——即**开思维链 +0.66 DS、+2.43 SR**。论文原文:"我们看到把解说任务当作思维链时有小幅提升,因此将其设为默认模式;不过没有它性能也不会退化太多,所以在推理速度要紧时不用思维链也是可行选项。"**本站原稿只引了后半句,把方向引反了,这里更正。** 论文的局限性一节说得最准:思维链"尚未显示出统计显著的驾驶性能提升"。

**所以这一节诚实的定性是作者自己给的那一个,写在表 2 的图注里**:"我们要强调,SimLingo 能够在纳入若干语言相关能力的同时,**保持与纯驾驶模型 SimLingo-BASE 相同的驾驶性能**。"——**持平,不是增益,也不是损失**。顺带两处标签更正:"纯视觉"在 SimLingo 语境里指**只用相机感知**,两个版本都是;基线是"无语言能力",不是"无语言模型"(它有一个 50M 的 LLaMA 架构解码器)。还有一处资历归属要说清:CARLA Leaderboard 2.0 挑战赛的成绩属于**无语言的那条臂**(论文表 1 脚注"我们把模型从 CarLLaVA 更名为 SimLingo-BASE 以保持一致"),完整版 SimLingo **从未在官方榜上评测过**;而基线在官方榜上的 DS 是 **6.25(MAP)/ 6.87(SENSORS)**,与 Bench2Drive 的 85.94 差两个数量级,论文明确警告两者不可比。

**闭环榜的图景:排序成立,但归因不成立。** 本站直读 `autonomousvision/Bench2Drive-Leaderboard`(自述更新于 2026-09-24,108 条非特权 + 3 条特权):榜首是 **BridgeDrive(LEAD)96.34 DS** 与 **TFv6 95.28 / 86.81**,都不是语言模型;名称可辨识为 VLA 的最高条目 LinkVLA 91.01 / 74.55、FIVE-VLA 90.95 / 77.27、BLUE 90.58 / 76.18,**差距是 4.3–5.4 分**。核验同时查出四处必须交代的问题:

- **榜页自己写明"本榜比较的是整个方法的最终表现,包括数据获取方式,而不只是架构"**——而决定性的对照就在同一页上:**BridgeDrive 出现了两次,同一篇论文、同一个架构,86.87 / 72.27 与 96.34,差别只在专家与数据集。单靠数据获取方式就带来 +9.47 DS 的摆动,接近语言/非语言那个差距的两倍。** 而榜首两条都依赖 LEAD 数据,最好的 VLA 条目都不依赖。**因此那 4.3–5.4 分至少同样可以由"谁用了最新的特权专家"解释,不能当作语言的架构性代价。**
- **这个榜不独立于它的头部参赛者。** 维护方 autonomousvision / 图宾根组同时是 TFv6、LEAD、TF++ 与 SimLingo 的作者方;而且**每一行都是论文作者自报**,维护者自己在页面上写明"结果为自报,从各自论文抄录"。它独立于基准的作者(Thinklab-SJTU),不独立于榜首。
- **一处榜内自相矛盾**:同仓库的 `main.tex` 把 BridgeDrive(LEAD)的 SR 记作 86.81,与 README 的 89.25 不一致(且与 TFv6 的 SR 完全相同,像是复制错误);另有 MemoryDrivoR 37.4 对 34.7、UniDriveVLA 78.73 对 78.37 两处不一致。**本篇凡引 89.25 均标注为"仅 README 口径"。**
- **语言/非语言这个切分是本站的编辑标注,榜上没有这一列**(它只分特权与非特权)。按名称审计能过(没有任何 *VLA 条目超过 91.01),但按名称标注会漏掉 VLADriver-RAG 89.12、AlignDrive 89.07、GraphPilot 88.89、PersonaDrive 88.95、KnowVal 88.42 这类语言条件化的候选——**它们也都没有突破约 91,所以天花板的结论仍然成立**。另外本站原稿说 TF++ 84.21 与完整版 SimLingo 的成功率"到小数点后两位完全相同"并以此立论,**这是过度解读**:67.27 = 148/220,Bench2Drive 的 SR 落在 1/220 = 0.4545 的离散格点上,相同只意味着两者完成了同样数量的路线。

**更锋利、而且不依赖上述归因的是 BLUE(EMNLP'26)给出的机制**:语言只在一小部分路线上起作用,而在那些路线上它"可能大幅改善,也可能大幅恶化";BLUE 的贡献是一个 **0.11M 参数的门控**,负责在大多数帧**把语言关掉**,换来 2.54 倍提速。另一侧,"Less Language, More Latents"用**不到 5% 的语言标注**拿到 87.98 DS / 70.46% SR;CausalDriveBench 评了 10 个驾驶 VLA 与 3 个通用 VLM,发现**因果问答准确率与轨迹准确率在模型间统计无关**。

> **本站判断(已按核验收窄)。** 不能说"语言买到的驾驶能力是负的",也不能拿 SimLingo 当受控消融。能说的是三条:① 在唯一一组同权重对照里,语言的收益是**正的但不显著**;② 作者自己的定性是**持平**——语言买到的是若干语言能力,不是驾驶分数;③ 到目前为止,**没有任何一个闭环榜首是语言模型,而最好的语言条目也没有突破约 91 这条线**,尽管这个差距的归因被数据获取方式严重混淆。**合起来:语言在驾驶闭环上至今没有被证明能买到驾驶能力,也没有被证明有害——它处在一个"花了很大代价、收益尚未可测"的位置。** 这比原稿的"接近零"弱,但这是证据的形状。

更锋利的是 BLUE(EMNLP'26)给出的机制:语言只在一小部分路线上起作用,而在那些路线上它"可能大幅改善,也可能大幅恶化";BLUE 的贡献是一个 **0.11M 参数的门控**,负责在大多数帧**把语言关掉**,换来 2.54 倍提速。另一侧,"Less Language, More Latents"用**不到 5% 的语言标注**拿到 87.98 DS / 70.46% SR;CausalDriveBench 评了 10 个驾驶 VLA 与 3 个通用 VLM,发现**因果问答准确率与轨迹准确率在模型间统计无关**。

## 4 · 让 VLM 驾驶看起来很行的那个指标,是可以空手刷的

这是本篇方法学上最该被记住的一节,也是本站 D43 第 8 节"等预算与密封评测"主题在另一个领域的完整重演。

**AD-MLP**(百度,2023)只喂自车状态——历史轨迹、速度、加速度、高层指令——**不接摄像头、不接激光雷达、没有任何感知**,在 nuScenes 开环规划上是 SOTA。本站直读其仓库的结果表:平均 L2 误差 **0.29 m**,对 VAD-Base 的 0.37、UniAD 的 1.03(其中 2s/3s 分项 0.26/0.41 为全表最优);README 还记录了一次修正——训练数据有误被外部指出后,平均 L2 从 0.23 改为 0.29、碰撞率从 0.12 改为 0.19。然后把它放进闭环:**Driving Score 18.05,Success Rate 0.00%**,除交通标志 4.35 外每一项多能力子分都是 0.00。

**一个在 nuScenes 开环上领先的模型,一条路线都跑不完。** 开环 L2 与闭环能力不只是弱相关,在这一对上是**反相关**的。

值得记上一笔的是,**作者自己把这件事说得比任何批评都狠**——仓库 README 原文:"尽管我们的模型在 nuScenes 数据集的范围内表现良好,我们承认**它只是一个无法在真实世界中工作的、不切实际的玩具**;在自车状态之外没有任何感知知识的情况下驾驶是一个无法逾越的挑战。"AD-MLP 从来不是一个在吹的工作,它是一份**诊断报告**——而领域花了两年才开始照着它改评测。

机制由 BEV-Planner(NVIDIA + 南京大学,CVPR'24)给出:**nuScenes 里 73.9% 是直线行驶**,保持当前速度、方向或横摆率在多数时候就是正确答案。两家基准维护者现在都白纸黑字:Bench2Drive 的 README 写着"作者应当停止报告 nuScenes 开环规划结果,审稿人不应当索要";carla_garage 写得更直接——"如果你在 2025 年评审一篇仅凭 nuScenes 规划结果立论的论文,我们请你拒稿"。

NAVSIM 作为诚实的开环替代品,把盲基线检查制度化了:其 devkit 自带 `EgoStatusMLPAgent`,文档原文(本站直读 `docs/agents.md`)——"`EgoStatusMLPAgent` 是一个**盲基线**,它忽略所有感知环境的传感器。该 agent 对自车状态(即速度、加速度与驾驶指令)施加一个多层感知机。由此,EgoStatusMLP **充当一个性能上界,即仅靠外推自车的运动学状态所能达到的水平**。"把盲基线写进 devkit、并在文档里把它定性为上界,是本站见过的最健康的基准设计实践。它在 navtest 上得 **65.6 PDMS**,而人类回放 94.8、匀速 21.6——**人类成绩的约 70% 是闭着眼睛能拿到的**,感知与推理一共只在 65.6→约 90 这一段里。而当前 navtest SOTA 不分架构都挤在 88–91:ResAD 用 ResNet-34、完全不带语言,88.8(换 V2-99 到 90.6);DAP 用 120M 参数的离散 token 规划器,90.0。**基准已经饱和,且不区分语言与非语言。**

**驾驶 VQA 那一侧塌得更彻底。** DriveBench(ICCV'25)把 12 个 VLM 在"干净图 / 受损图 / 纯文本无图"三种输入下评测:

| 任务 | GPT-4o 给干净图 | GPT-4o **不给图** |
|---|---|---|
| planning | 75.75 | **73.21** |
| perception | 35.37 | **36.48**(不给图反而更高) |
| behavior | 45.40 | **50.03** |

作者的结论是模型在"依据通用知识或文本线索生成看似合理的回答,而非真正的视觉接地"。DriveLM 自家微调的专才在去掉图片后也只从 68.71 掉到 65.24。指标本身还火上浇油:ROUGE-L 常年在 0.2 附近,而 DriveLM 在 ROUGE-L 上赢其它 VLM、在 GPT-score 上输——**微调的增益很大程度是答案模板匹配**。人类评分者在干净图的感知任务上只拿 47.67,说明这套基准自己的天花板都没标定好。

## 5 · 产业的自答:三家都把语言移出了出控制量的那条路径

比任何论文都有说服力的,是手里有最多车、最多算力的那几家自己做了什么。

**小鹏——第二代拆掉了"语言转译"这一段。** VLA 2.0 是 视觉 → 隐式 token → 动作,官方表述是三段式的 视觉识别→语言转译→动作生成 存在信息损耗与延迟,其框架是**语言是对物理世界的一种"高度有损的压缩"**;定性从"思考后行动"改为"直觉式反应 / 看到即做到"。**但核验在这里收窄了三处,都必须照改:**

- **"把语言层删了"是过头的说法。** 小鹏删掉的是实时路径上**解码为文本**的那一段,不是语言:按其自身解释的技术转述,语言仍作为并行/辅助输入流保留(路牌文字、手势),**车端仍是一个语言预训练的多模态 Transformer**,产品仍叫 VLA,而监督仍由一个 72B 语言预训练云端模型蒸馏而来。**准确的说法是:这不是无 LLM 的控制路径,而是无"解码成文本"的控制路径。**
- **"从约 200 ms 降到 <80 ms"的那个起点没有一手来源**:200 ms 只作为媒体对"传统架构"的泛述出现,不是小鹏实测的一代延迟。**只有 <80 ms 这个厂商数字存在,降幅本站不再引用。**
- **2,250 TOPS 是三颗芯片的平台合计**(3 × 约 750 TOPS"有效算力"),"有效算力"是小鹏自定义的利用率折算指标,**本站读到的任何来源都未声明精度(INT8/FP8/INT4)**;"1 颗顶 10 颗 Orin-X"是把自家利用率假设套到竞品上得到的,按标称 INT8 算约为 3 倍。

**华为——明确不走 VLA 路线,但流传最广的那句引语本站无法归属。** 可确认的部分(2025-08-28,多家独立中文媒体口径一致):智能汽车解决方案 BU CEO 靳玉志表示华为不走 VLA,更看重 WA(World Action)。而**他给出的理由是认识论层面的,不是延迟或体积**——按 IT之家 / 新浪的转述:VLA 路线靠语言模型学习网络知识,"**这样的路径看似取巧,其实并不是走向真正自动驾驶的路径**",而 WA 是"直接通过 vision 这样的信息输入实现控车的大模型……**无需把各种各样的信息转成语言**"。

> **这里有一处本站必须公开更正的引用。** 原稿把"**VLA 太大太慢了**""无法有效处理空间信息""投机取巧"作为靳玉志的公开表述引用。核验查明:这组说法**唯一可定位的出处是一个知乎回答**,其将其归于"华为的人"在 B 站采访中的说法——即**匿名员工在用户生成问答站上的转述,不是 BU CEO 的在录表述**;且靳玉志说的是"看似取巧",与"投机取巧"在语气上并不相同。**本站此后不再以靳玉志名义引用"VLA 太大太慢了"。** 同样地,"没有语言层,没有思维链""MoE 路由""四路传感器输入""1/5 的算力"这一组架构描述,**来源均为中文汽车自媒体的科普/专栏文章,不是华为文本也不是靳玉志的话**,本篇将其降级为第三层级转述,不作为华为口径。ADS 4 的 WEWA 架构端到端延迟较上一代降低 50% 为厂商自报。

**Waymo——把 VLM 放在慢分支,而不是放在控制路径之外。** 核验在这里也纠正了本站原稿:

- **原稿引用的那句"视觉语言模型擅长高层推理,但对实时控制而言太慢,且单独使用时空间感知不足",核验无法在 Waymo 文本中定位,本站撤回该引语。**
- **"把 VLM 排除在实时控制之外"是过头的。** 按 Waymo 自己的描述:Sensor Fusion Encoder 融合相机、激光与毫米波并产出物体、语义与丰富嵌入;Driving VLM 用相机数据、以 Waymo 驾驶数据微调、由 Gemini 训练;**两者都馈入 World Decoder**,而 World Decoder 预测他车行为、产出高精地图、**生成本车轨迹以及用于轨迹校验的信号**。**准确的说法是:Waymo 把 VLM 移出快反应路径、让它处理罕见与新奇的语义场景,而产出轨迹的 World Decoder 同时消费快慢两路**——这是两速分工,不是排除。
- **校验层存在,且是一手确认的,但它本身是学出来的。** Waymo 2025-12 的原文为"**一个独立而严格的车载校验层,随后验证由 Driver 的生成式 ML 模型所产出的轨迹**";而 Waymo 对这一层的描述是"**一个独立的、基于 AI 的安全系统**",通过引入强化学习与受生成式 AI 启发的推理等技术,对照硬性物理约束与交通法规检查规划,"**充当硬性兜底**"。**所以它不是规则检查器——被分离出来的是校验这一层,不是一个独立的非学习式裁决者。** 本篇其余各节凡提及此层均按此口径。

Waymo 刻意保留"嵌入 + 结构化物体/路网"的混合表示"而非纯端到端,以保持系统可验证";教师模型"大到无法在车上运行",经蒸馏成学生模型。而 **EMMA——Waymo 真正那篇"Gemini 上车"的论文——是纯研究**:离线评测、无闭环、不接激光雷达与毫米波、坐标用文本编码、推理延迟从未被刻画。Gemini 确实在 2026 年上了 Waymo 的车:**在座舱里,当乘客助手**。

> **本站判断(已按核验收窄)。** 三家的理由**并不是同一套**——小鹏讲有损压缩与延迟,华为讲"看似取巧"的认识论,Waymo 讲实时性与可验证性;而且这是一场尚未定论的分歧,而非共识:中文行业媒体的概括是"小鹏、理想向左,华为向右",**理想在 MindVLA 里保留了语言**。能站住的收窄结论是:**在三家各自的架构里,语言都被移出了逐帧产出控制量的那条路径**——小鹏移出了文本解码,华为不引入语言转换,Waymo 把它放到慢分支。**它们是在自己的钱和自己的事故责任上做的这个选择**,这一点仍然比任何单篇论文的消融更有分量;但没有任何一家公布了闭环或延迟的第三方测量,所以这是"三家的工程选择一致",不是"三家证明了语言无用"。

## 6 · RL 与世界模型:奖励其实是"像不像人类日志"

驾驶在 2026 年确实变成了一个 RL-on-verifiable-reward 的领域——但**真正可验证的那个奖励,是"到某条被记录的人类轨迹的距离"**,本质是带排序步骤的模仿学习。

最清楚的一手物证是 NVIDIA 自家的配方 README(本站直读 `NVlabs/alpamayo-recipes`),而它**逐字就是 LLM 的那套 RL 栈**:GRPO(直接引用 DeepSeekMath, arXiv:2402.03300)、Cosmos-RL 把训练的策略副本(FSDP)与生成的 rollout 副本(vLLM 引擎)分开、控制器负责派发 rollout 与权重同步。作者给出了训练 Alpamayo 1.5 实际用的集群配置:**64 个策略副本 × 每副本 8 卡 = 512 张策略卡,外加 128 张 rollout 卡,合计 640 卡 / 80 节点**,全局批 64 × 40 = **2560**,`n_generation=12`,lr 2e-6,每 5 步同步一次权重。这张表与本站 D33 那篇讲 verl 的调度图是同一个形状——**驾驶的 RL 基础设施已经完全是 LLM 的 RL 基础设施**。

而释出的演示奖励只有两项:**ADE(预测轨迹与真值 XY 轨迹之间的平均位移误差)与舒适度分数**(加速度、加加速度、横摆率等落在舒适界内的时间步占比),外加一个 ADE 超过阈值(默认 3.0 m)即把奖励钳到 −1 的闸门。本地演示跑出来的数字,README 自己给了:**奖励从 −0.28 升到 −0.21,轨迹 L2 从 1.66 降到 1.34**。

**所以这个"验证器"就是人类司机被记录下来的那个未来。** 它在 SFT 模型已能产出的样本里重排序,**无法发现任何没有人类开过的机动,也没有任何反事实伤害的概念**。NVIDIA 自己把这个演示奖励限定为"只给 rollout 的轨迹部分打分"。

两处细节核验后要改,都往更准的方向:

- **本站原稿说"推理奖励并未释出",这是错的,此处更正。** NVIDIA 在当前 main 上确实发布了:`rewards/aggregated_reward_with_reasoning.py` 存在,给思维链打分并加了第二道闸门(`reasoning_threshold = -0.4`);配套的 `toml/alpamayo_rvla_rl_local_test_with_reasoning.toml` 设 `reasoning_weight = 0.3`、`reasoning_grader_type = "lingo_judge"`;另有独立的入口脚本、可继承的 `BaseReasoningGrader`,以及已释出的推理标签(`reasoning/ood_reasoning.parquet`)。那句"只给轨迹部分打分"的限定**只针对默认演示奖励,不针对整个发布**;README 自身是不一致的——FAQ 还写着"将很快释出",而正文已把它记作已发布。**不过这条更正并不削弱本节的要点,反而把它确证了:实际发布的推理评分器就是 Lingo-Judge——一个微调过的序列分类器。连"推理对不对"这件事,奖励也是一个学出来的模型说的,不是一个可执行的检查器。** 这与本站 D43 第 4 节那张"奖励接地四档表"对上了,而驾驶落在最弱的一档。
- **3.0 m 这个闸门是写死的,不是可配置项**(README 说"默认 3.0 m"容易让人以为是旋钮,但两个奖励文件里它都是硬编码字面量,只有权重来自 TOML);而"钳到 −1"的说法也不够准——按发布的本地测试权重(`traj_l2_weight` 0.4、`comfort_weight` 0.1,舒适度分在 [−1, 0]),闸门内的奖励区间大致是 [−0.5, 0],**所以 −1 是一道落在整个闸门内区间之下的不连续悬崖,不是某个连续函数的下界**。

**而最该被记住的一条,藏在 README 的 FAQ 里,而且它经核验是逐字成立的。** 问"到底是什么在被 RL 后训练",答:被 RL 后训练的是 **VLM 骨干**(ReasoningVLA 路径的离散动作 token 变体,自回归产出文本与离散轨迹 token);而"**动作专家头(基于流匹配的连续动作)不由这条 RL 管线训练**",针对动作专家路径的 RL"将在未来版本中提供"。核验还补了一条更硬的物证:**导出的 checkpoint"只包含 VLM 骨干权重"**,若拿它去走动作专家路径,"动作专家权重将是随机初始化的"。换句话说:**在 NVIDIA 这套公开配方里,RL 优化的是那个说话的部分,真正输出连续控制量的那个头被绕过去了。** 这把本篇第 1 节的三分法,在一家最有动机把语言推上控制位的公司的代码仓库里,又验证了一遍。配方里也**没有任何一种驾驶能力证据**——唯一的成绩数字就是上面那组本地演示曲线。

小米 EV / 华科的 MindDrive(ECCV 2026)是更好的在线 RL 存在性证明,设计也更聪明:一个 Qwen 骨干(0.5B / 2.5–3B)配两组 LoRA——决策专家出离散的语言化 meta-action,动作专家把它映射成 VAE+GRU 航点——用 PPO 在真实 CARLA rollout 的稀疏成败回报上优化。**诀窍是让 RL 在有限离散的语言动作集上探索,而不是连续轨迹**,这才让探索可行。成绩 DS 78.04(0.5B)/ 80.59(3B)。核验确认了环境是 CARLA 0.9.15、评测是 Bench2Drive 闭环、**仓库里没有任何东西碰到车**,但同时收窄了两处:**"在线"是算子驱动的批式 on-policy PPO,不是持续学习的车**(释出的脚本是两次手动调用:先把 rollout 收集到磁盘,再喂给 PPO 训练);而**那条"性能随 RL 轮数非单调"的消融不在官方 README 里**,只见于第三方论文笔记(其文本经机器比对与论文原文吻合),具体是 rollout 轮数超过 2 时 **DS 从 78.04 掉到 73.69**,作者归因于灾难性遗忘。**所以准确的说法是"超过调好的那个最优点之后更多 RL 会变差",不是"RL 净有害"。** 而且它只在 CARLA 上、只在挑过的可探索路线上。

**决定性的负面数据在第三方闭环榜上**:所有 RL-on-VLA 条目都远低于从特权规则专家蒸馏来的朴素模仿方法——IRL-VLA-RL 55.36、DriveDPO 62.02、Raw2Drive 71.36、MindDrive 78.04、AutoVLA 78.84,对 TFv6 95.28 与 BridgeDrive 96.34。更刺的一条:**Orion-Lite 在推理时把 LLM 和文本提示删掉**、只把教师的规划 token 表示蒸馏进一个轻量 transformer,得 80.57,**高于 ORION-7B 的 77.74**。

## 7 · L4 的真实账本:谁在跑、靠什么、要多少里程

**定义先行,因为定义本身就做掉了一半的工作。** 核验直读了 J3016_202104 全文,结论要比本站原稿精确一些:L3→L4 的分界**主要**在于**谁来做动态驾驶任务的回退**,而标准把它称为一项**能力**——§5.5 注 1:"L4 的 ADS 有能力自动执行 DDT 回退,并在用户未恢复执行 DDT 时达成最小风险状态。**这项自动 DDT 回退与最小风险状态达成能力,是 L4 与 L3 的 ADS 特性之间的主要差异。**"§3.12 注 1 并指出"DDT 与 DDT 回退是不同的功能,具备其一并不必然意味着具备其二"。**所以"不是能力问题"这个说法要撤回:它确实是一项被追加的机器能力,只不过不是"在 ODD 内把车开好"那种能力。**

核验还补了三条本站原稿漏掉的 L3/L4 差别,每一条都加重而非减轻结论:

- **L3 的定义范围比"全部 DDT"更窄。** §5.4 的措辞是 ADS 执行全部 DDT"**在例行/正常运行下**",而 §3.26 把例行/正常运行定义为"在其规定的 ODD 内(若有),**且无 DDT 性能相关的系统失效正在发生**"。**失效工况因此落在 L3 的定义范围之外、落在 L4 之内。**
- **L3 的用户还得兜住 ADS 不监控的那些车辆失效。** §5.4 注 3:用户需"对车辆系统中明显的、DDT 性能相关的系统失效保持接受状态,**而这些失效未必会触发 ADS 发出的干预请求**,例如车身或悬架部件断裂"。
- **边界是"保证覆盖",不是"具备能力"。** §3.12 注 2:一个 L3 特性可以在某些情形下达成最小风险状态,"但在其他情形下不能……**它无法保证在其 ODD 内的所有情况下都自动达成最小风险状态**"。

而 **L5 与 L4 只差一个比特——有没有预先规定的 ODD**。所以"LLM 够不够 L4"实际问的是**最小风险状态在失效工况下的可达性与失效模式覆盖**,不是驾驶技巧;而"够不够 L5"问的是**无界域的可验证性**。

**今天在跑 L4 的是谁,用的是什么。** Waymo 截至 2026-03-31 累计无人驾驶载客 **2.206 亿英里**(凤凰城 8060 万、湾区 6710 万、洛杉矶 5180 万、奥斯汀 1580 万、亚特兰大 540 万),约 3,871–4,000 辆车,每周超 50 万次付费行程,到 2026-09 覆盖 15 个美国都会区。萝卜快跑 22 城、每周超 25 万单;小马智行 1,975 辆(2026-06-30);文远知行约 1,800 辆机器人出租车。

**而没有任何一家已部署的 L4 运营商把语言模型放进控制回路。** 小马智行第七代车载平台是 1,016 TOPS,跑的是世界模型而非 LLM;Autoware/TIER IV 是唯一拿到监管许可的开源 L4(日本,付费巴士,固定线路)——**而它是模块化栈**。

**中国这边的教训更直接:L4 是靠"减少通用性"拿到的**——地理围栏 + 高精地图 + 远程接管 + 精选车队,不是靠加语言模型。而且至今财务上仍然吃力:文远知行 2025 财年营收 6.85 亿元、净亏 17 亿元;小马智行营收约 9000 万美元、净亏 7680 万美元。

**然后是里程的算术。** RAND RR1478(本站读了全文):要在 95% 置信度下证明致死率不高于人类的 1.09/亿英里,需要 **2.75 亿英里**无失效里程;要把这个率钉到 ±20% 需要 **88 亿英里**;要证明改善 20%(95% 置信、80% 功效)需要 **110 亿英里**;证明改善 5% 需要 **2150 亿英里**。注意伤害类(77/亿英里)与警方报案类(190/亿英里)只需 390 万与 160 万英里——**这解释了为什么所有厂商的安全宣传都停在"伤害"口径而不碰"致死"口径**。

这同时意味着:**Waymo 在 2.206 亿英里上的重伤头条,实际建立在 47 起绝对意义上被避免的事故上**;其中仅 5670 万英里经过同行评审(任何伤害降低 79%,95% CI 71–85%),而且作者只有 Waymo 自己,人类基准是建模出来的(县级行驶里程、地理加权、32% 漏报膨胀、两侧都排除高速)。加州 DMV 的脱离报告不能替代——**DMV 自己声明它"无意用于公司间比较"**。

**扩大规模能解决长尾吗?目前的证据说不能。** Waymo 自家的 IsoFLOP 研究(44.7 万小时、5.41 亿样本、84 个模型)得出 N_opt ∝ C^0.63、D_opt ∝ C^0.44,且在同等算力下这些运动模型**比语言模型小约 50 倍**;但作者自己写明"**算力跨度不足以确立开环或闭环的幂律**"。别处的结果更冷:一篇工作发现开环有幂律而**闭环没有**;NVIDIA 的研究发现开环 FDE 以约 −0.40 的指数改善,而**闭环的平均无失效里程在约 256 小时处饱和**;Alpamayo 从 10B 到 34B(8 万→11.5 万小时),minADE 从 0.916 m 动到 0.911 m,**在误差棒内**。特斯拉则公开把"约 10 倍参数"的模型从 v14 推迟到 v15,理由是小模型改进得更快。

## 8 · 可认证性:这才是结构墙

前面几节的约束,至少方向上是工程问题。这一节的不是。

**ASIL-D 要求最坏执行时间(WCET)有界。** 自回归解码的 token 数是**数据相关**的,而投机解码**按构造**让延迟变成随机的——这恰好是认证体系禁止的性质。一篇系统性综述调查了 AI 加速器的安全工作,发现**没有一项**给出 WCET 分析。

**形式化验证在驾驶策略上确实有效,但只在 5,152–101,888 个 ReLU 神经元的规模上**,因为界传播的代价随网络规模增长;一个 10B 的 VLM 比这个尺度大 **5–6 个数量级**。

**而标准本身假设失效模式是可枚举的。** ISO/PAS 8800:2024 是个框架,**对机器学习没有 ASIL 映射**;世界上第一张依其颁发的证书(吉利,SGS-TÜV 萨尔,2025-08)认证的是**安全流程,不是某个策略的行为**。

**2026 年的监管走向把这一点坐实了。** UNECE WP.29 于 **2026-06-24** 通过首个全球 ADS 法规与 GTR(美、中、欧、日、加、英支持),要求:经审计的安全管理体系、**可信测试**(含满足可信性准则的虚拟工具链)、一份论证"无不合理风险"的**结构化安全论证**,以及持续的在役监测与报告。**这是过程与证据路线,不是里程路线**——而这恰恰是一个随机、不可复现的生成式策略最难论证的地方。

中国侧:首批 L3 生产准入 2025-12-15 落地,**窄到不可思议**——长安深蓝与北汽极狐两款,限定在点名的路段(如重庆内环高滩岩立交—赖家桥立交),车企明说存量 L2 车辆无法升级。GB 44721-2026 带统一的 L3/L4 测试场景框架,2027-07-01 生效;GB 47955-2026(组合驾驶辅助安全要求)2026-06-27 发布、2027-01-01 生效,**定义上就要求驾驶员持续观察并保持控制**。**没有任何乘用车 L4 型式批准存在。**

小米 SU7 致死事故(2025-03-29,116 km/h 下使用 NOA)之后,工信部 2025-04-16 的闭门会直接禁用"自动驾驶""智驾"等宣传用语、禁止以用户做公测、把涉安全的 OTA 纳入召回级审批;小米随后于 2025-09-19 召回 116,887 辆 SU7 标准版,原因是 L2 高速 NOA 在极端场景下"识别、预警或处置不足"。**监管方对这类系统的既有认知就是:驾驶员监督、OTA 受控、宣传受限。**

## 9 · 中国与昇腾:车端 NPU 和数据中心 NPU 是两个世界,华为是唯一例外

这一节是本站的主场,结论对读者判断"国产栈能不能承接"最直接。

**工具链在前端收敛、在底层完全分叉。** 地平线的流程(本站直读 D-Robotics 文档):ONNX 进 → `hb_mapper`/`horizon_nn`/HMCT → `hbdk-cc` → 一个闭源的 `.bin`/`.hbm`,内含"针对特定 BPU 架构的二进制指令与权重数据",用 `--march bayes-e`/`nash-e` 指定;`horizon_plugin_pytorch` 提供 qint8/qint16 的 PyTorch QAT,但 **int16 仅 BAYES/BAYES_E 及之后支持,且不支持权重的 int16 量化**;ONNX **导出**明确"不支持 onnx run"(仅供可视化);**不支持非 4D 的模型输入**;任何 C×H×W > 8192 的算子回落 CPU;Softmax 经常落在 CPU 上。

**这是一个 AOT、定形状、没有 kernel 语言的世界**——与 CANN/AscendC(2025-08-05 开源,给你 kernel 语言、动态形状、KV cache 与集合通信)正好相反。**单是"不支持非 4D 输入"这一条,就对 LLM 的 `[batch, seq]` 张量充满敌意。**

**华为是唯一的真收敛案例。** 昇腾 610(车载,7nm,>50 亿晶体管,10 个达芬奇核、每核 4096 MAC、3D CUBE,200 TOPS INT8 / 100 TFLOPS FP16,位于 MDC 之下)**与数据中心的昇腾 910 线共享达芬奇核与 CUBE 原语**;而昇腾云侧的自动驾驶训练路径**本身就是这套 LLM 栈**——DrivingSDK / `mx_driving` 构建在 CANN + torch_npu 之上,对 PyTorch 2.1.0/2.6.0/2.7.1/2.8.0,编译 `DeformableConv2d`、`MultiScaleDeformableAttn` 这类自动驾驶专用算子。

**但规模宣称全是自报,而且方法上站不住。** 华为的安全头条——"严重碰撞平均安全里程为人类的 3.58 倍或约 4.9 倍"、"避免 447.9 万次碰撞"、累计 100 亿公里(2026-04-19)升至 128 亿——全部厂商自定义。"避免的碰撞"是一个无法证伪的反事实计数,无第三方审计;而"重大事故间隔里程"的对比,是拿一支高价、以高速路为主、车龄新、车主富裕的车队去比全中国驾驶员均值——**这是选择偏差,不是等暴露对比**。

**而评测的 harness 敏感性在这里肉眼可见**:P3 中国 2026-05 的评测把华为 ADS 4.1 排第一(4.46)、小鹏 VLA 2.0 第二(4.33)、理想 AD Max 第三(4.06);懂车帝的测试却把特斯拉 Model 3/X 排一二、华为系列在其下。**同样的车,不同的 harness,排序反转**——而中国至今**没有任何密封的、第三方执行的、留出的驾驶基准**,于是没有等预算对比,也没有污染控制。

华为自己的验证证据是 **6 亿公里的自家云端仿真**,难例由自家世界引擎扩散模型生成、密度号称是真实世界的 1000 倍——**在自己生成的难例上训练、再对着自己的仿真器报告改进,正是本站 D43 反复点名的那种训练集污染失效模式**。

## 10 · 本站的回答

**对 L4:可达,而且已经被达到了——但达成它的架构,是把一个确定性的、蒸馏过的、远小于语言模型的策略放在控制位上,把 VLM 移出快反应路径,再在生成轨迹与执行之间加一层独立的校验层(按 Waymo 自己的描述,这一层也是学出来的,作硬性兜底)。** 一个车载 LLM 作为"真正开车的那个东西",不在这条路上。

把三堵墙按性质分开:

| 墙 | 性质 | 依据 |
|---|---|---|
| 车端带宽与延迟 | **工程问题**,正在被解决;且约束的是**每帧吐词数**,不是参数量 | AI5 称 144 GB / 约 5× 带宽;NX9031 称 546 GB/s;厂商实际出货 3–4B 并把 token 吐出工程掉(小词表 / 投机 / 并行解码 / MoE) |
| 语言买不到驾驶能力 | **经验问题**,目前**未被证明**(既未证实也未证伪) | SimLingo 唯一同权重开关 +0.66 DS 但不显著,作者定性为"持平";闭环榜首非语言但归因被数据获取方式混淆(同架构换专家 +9.47 DS);驾驶 VQA 不看图也能答 |
| 自回归生成 vs 硬实时期限 | **结构问题** | ASIL-D 要求 WCET 有界;token 数数据相关;投机解码按构造随机 |
| 随机策略的可验证性 | **结构问题** | 形式化验证上限约 10⁵ 神经元,10B 模型差 5–6 个数量级;ISO 8800 无 ML 的 ASIL 映射 |
| 长尾的统计证明 | **结构问题** | RAND:2.75 亿英里证致死率、110 亿英里证改善 20%;闭环 MDBF 在约 256 小时饱和 |

**对 L5:它不被上面任何一条阻挡,它被定义阻挡。** L5 意味着没有 ODD,而**在用的每一件认证工具——ISO 34503 的 ODD、UN R157、UL 4600 的安全论证、2026 年的 UNECE GTR——都建立在"把 ODD 框起来"之上**。无界域没有有限场景集、没有安全论证、也没有在役监测方案。这不是工程积压,这是结构性的。连 carla_garage 的维护者都把话说得很明白:今天的科学"足以支撑 L4 的部署",而"实现 L5 自动驾驶将需要根本性的科学进步"。

**那语言在哪儿有用?** 三个地方,而且都真实:离线自动标注与难例挖掘;车上作为**慢速、回路外**的语义监督者,盖住罕见的长尾语义(Waymo 的"车辆起火→改道");以及教师侧的推理与数据合成。**它买的是可解释性与监督接口,不是驾驶能力。**

**对本站主线(RL-on-NPU)有三条可带走的:**

1. **驾驶 RL 的奖励问题比 LLM 的更糟,而且 RL 还没碰到控制量。** NVIDIA 的公开配方把 GRPO 那套(640 卡、全局批 2560、组大小 12)原样搬了过来,但可验证的奖励退化成"到人类日志轨迹的 L2 距离 + 舒适度",它只能在模型已有的样本里重排序,**无法发现没有人开过的机动**;而配方自己声明被 RL 优化的是 VLM 骨干,**流匹配的动作专家头不在这条管线里**。本站因此认为:当下"驾驶 RL"的进展,基本等价于"让模型把人类轨迹说得更准",离"让策略学会一个人类没示范过的更安全机动"还隔着奖励设计这一整层。
2. **世界模型当评测器,缺的是那个没人公布的数。** 仿真与真实的排序相关性在驾驶领域无处可查;机器人领域公布过的范围是 ρ=0.40 到 r=0.99。在这个数公布之前,"在世界模型里做闭环 RL"的所有增益都无法被定价。
3. **车端 NPU 不会自动继承数据中心 NPU 的生态**,唯一的例外是华为——昇腾 610 与 910 共享达芬奇核与 CUBE,而云侧训练路径就是 CANN + torch_npu。**这是国产栈在自动驾驶方向上唯一一条"训练与部署同族"的路径**,也是本站此后应当盯住的那条线。

## 11 · 核验改写了什么,以及本站仍未核实的

- **对抗核验跑完了,而且它改写了本篇三处主干论证。** 六路调研每路取两条承重主张送核验,共 **12 条判决:9 条 partially_correct、3 条带 refuted 标记**。被改写的三处是:**① 第 2 节**——"算术预测的参数量与实际出货吻合到 2 倍以内"被推翻(两个举例对象都不是出货的车端 VLA;真实出货高出上限约 4 倍;"每帧 10 token"是不可观测的自由旋钮);本站改用核验留下的、更强的说法:**参数上限没有生效,token 预算生效了**。**② 第 3 节**——SimLingo 基线对完整版**不是受控消融**(论文附录 B.3 列出四处同时改动,且作者明说未在新设置下重跑基线),而论文唯一同权重的语言开关**方向为正**(+0.66 DS / +2.43 SR,不显著);本站原稿只引了"关掉思维链无明显退化"的半句,把方向引反了,小节定性已从"接近零"改为"按作者自己的说法是持平"。**③ 第 5 节**——"VLA 太大太慢了"等一组说法**无法归属于靳玉志**(唯一可定位出处是知乎上对匿名"华为的人"的转述),已撤回;Waymo 那句"对实时控制太慢"的引语**在 Waymo 文本中无法定位**,已撤回;"把 VLM 排除在实时控制之外"收窄为"移出快反应路径,World Decoder 仍同时消费快慢两路";车载校验层**本身是学出来的**,不是规则检查器。另有若干收窄已就地写入各节(J3016 的 L3/L4 差别是一项追加**能力**;Alpamayo 的推理奖励**其实已发布**,本站原稿说"未释出"是错的;3.0 m 闸门是硬编码;MindDrive 的非单调消融不在官方 README 里)。**本篇结论未变,但支撑它的依据已经换过一轮——这正是核验该起的作用。**
- **仍未经对抗核验的部分**:每路只取了两条主张送核验,因此第 7、8、9 节的大部分里程数字、监管日期与中国厂商口径**未逐条复核**;以过往经验,核验通常会收窄其中一到两成。引用前请以此为准。
- **小鹏车端模型规模的那处矛盾已被核验解开,但解开的方式是"两个数都站不太稳"。** 两个流通数字属于**不同时点与不同配置档**:约 3B 一说对应 2025-11 的第二代 VLA 发布,而且核验查明它**只出现在小鹏用户论坛的措辞里,不见于官方文本**——官方用词只是"数十亿参数";7B 一说对应 **2026-09-22 的 XOS 6.3.0 OTA**("端侧模型参数量提升 3.5 倍"),而核验**未能在任何可索引页面上定位"70 亿级稠密参数"这一精确表述**,独立媒体一致携带的只有相对口径("扩展了 3.5 倍"),且"稠密"与否无法从任何可得材料证实。此外该次 OTA 实际分**三条交付线**(三颗图灵芯片的 Ultra/Ultra SE 走 VLA 2.0;单图灵的 Max 走蒸馏的 VLA 2.0 Lite;双 Orin-X 车型走另一条更轻的线),**所以不存在单一的"小鹏车端模型规模"**。本篇凡引这两个数字均按此限定。
- **绝大多数厂商与媒体站点在本环境被代理拦截**(xiaopeng.com、huawei.com、hiascend.com、waymo.com、nvidia.com、arxiv.org、huggingface.co 等),车企口径均经搜索摘要读取;可直读的一手来源主要是 GitHub 仓库的 README、文档与代码,以及部分可达的技术文档。
- **第 2 节把 FlashDrive 外推到 Thor-X/Orin-X 的那组数字是本站的算术,不是实测**,且偏乐观(车规 NPU 缺少其依赖的 kernel 栈)。芯片带宽取自第三方规格聚合站,NVIDIA 官方文档不可达。
- **Waymo、华为、小鹏的所有安全与规模数字均为厂商自报**,其中"避免的碰撞数"是不可证伪的反事实计数;Waymo 仅 5670 万英里经同行评审,且作者只有自己。
- **中国没有密封的第三方驾驶基准**,所有跨厂商排序都随 harness 翻转(P3 与懂车帝的结果互相矛盾),因此本篇不列任何中国厂商间的能力排名。
- **Bench2Drive 榜单的每一行都是论文作者自报**,维护者自己在页面上写明"结果为自报,从各自论文抄录",且方法在数据集、预训练、训练算力、推理算力、参数量、IL/RL 等多个轴上都不同——**不是等算力对比**。

## 下一步看什么

1. **仿真与真实的排序相关性。** 这是整个领域最该被公布、却至今无人公布的那个数。谁先在驾驶上发表一个可复现的 sim-vs-real rank correlation,谁就定义了"世界模型可否用作评测器"的标准。
2. **GB 44721-2026(2027-07-01 生效)的统一 L3/L4 测试场景框架落地形态。** 这是中国第一次有统一的场景口径,它会直接决定国产 L3/L4 的审批节奏,也是未来跨厂商比较唯一可能的公共基座。
3. **UNECE 2026-06-24 那份 GTR 的"可信测试"细则。** 虚拟工具链要满足什么可信性准则,实质上就是在回答"生成式策略能不能进安全论证"。
4. **昇腾 610 后继与 MDC 的 CANN 版本对齐。** 若车端与云端的 CANN/算子栈真正统一,国产栈就拥有自动驾驶方向上唯一一条训练—部署同族的路径;本站会盯住 DrivingSDK/`mx_driving` 与主线 CANN 的版本跟随。
5. **小鹏车端模型规模的权威口径**,以及 VLA 2.0 是否公布任何闭环或第三方评测数字。
6. **是否出现第一个把语言通道的收益在闭环上证伪或证实的受控消融**(SimLingo 之后还没有第二个同等质量的对照)。
