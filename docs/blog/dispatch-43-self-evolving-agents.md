# Dispatch 43 · 自进化全景:五份综述的分歧、θ 与 Σ 的分界,以及三支路线各自的失效模式

*2026-09-17 · NPU Frontier Dispatch · self-evolving-agents / self-improvement / continual-harness / RL-on-NPU*

> **TL;DR** — 自进化(self-evolving agents)在 2026 年成了显学,但**这个方向现在有五份互不兼容的综述**,连"共进化"这个词都被争夺:厦大把"多智能体互相适应"列为共进化之首,微软研究院明确**排除**它,认为共进化必须有人类参与。本篇以综述之综述的方式梳理全景,并用九张论文原图串起三支路线。**最精确的形式化来自 Schmidhuber 组**:一个 agent 是 `A_t = (θ_t, Σ_t)`,其中 `Σ := (p, m, T, g)` 是提示词、记忆、工具、控制逻辑;**动 θ 是标准 RL,动 Σ 是在改 MDP 本身,没有 RL 对应物**——这个 Σ 与本站 D41 记录的 Prime Agent harness `H=(p,G,K,M)` 是**同一类对象的两种切法**,但两个四元组并不逐项对应,也不是同一构造(见第 2 节的更正)。三支路线的论文数是 **模型侧 76 / 环境侧 110 / 共进化 25**,共进化几乎全是 2025–2026 年的工作。逐支看机制:**模型侧**的推理时自我纠错在没有外部信号时是**净负**(GPT-4 在 GSM8K 的 200 题随机子集上 95.5 → 91.5 → 89.0,GPT-3.5 在全集上把对的改错 8.8% 多于把错的改对 7.6%),早期论文的增益来自用真值决定何时停手;零数据自博弈靠三种接地活下来——可执行验证器、零和博弈、语料。**环境侧**最热,冻结权重改一切,而记忆系统的工程核心在**写入与准入策略**,不在相似度检索——但要当心:几个被反复引用的"遗忘机制"在代码里并未真正启用(见第 5 节的更正)。**共进化**的自适应课程本质上是**梯度信号保全装置**:RLVE 把它命名为 effective prompt ratio,但**论文全文没有给出任何数值**;可核实的只有方向——静态低上限区间的比例会掉到零,静态高上限则显著低于自适应,而预言机选定的那一档,论文自己只写到**持平**。失效模式高度一致地指向同一处:**在自进化系统里,打分者位于被打分者的下游**——R-Zero 的伪标签准确率三轮内从 79.0% 掉到 63.0%——但这不是打标器变差,而是**课程奖励把训练分布推到了多数投票最不可靠的位置**;用无参考 LLM 裁判做自博弈,裁判通过率从 0.72 涨到 0.94 而**真实准确率始终停在 0.20**;贪心接受规则下 **30–42% 的提交是假阳性、10–33% 有害**。评测侧的结论最冷:**等 rollout 预算下,朴素并行采样 72.3 分 > 演化 67.4 分**;密封评测中可见集从 0.10 涨到 0.63,隐藏集只从 0.13 动到 0.26。产业侧则高度一致:**所有已出货的自进化都写文本、不写权重**,三个机械原因是前缀缓存经济学、文本产物可 diff 可回滚可审计、反思式文本优化在真实 rollout 预算下比 RL 高约 35 倍样本效率。对昇腾:推理时演化**已经免费**,在线训练演化要额外付 HCCL 重建与 ACL graph 重捕获的税,而记忆演化有一条明确设计规则——**把演化中的记忆放成稳定前缀**,否则每轮 rollout 都会击穿自动前缀缓存。

## 1 · 先读地图:为什么需要读五份综述

自进化不是一个有共识定义的领域。它是**同一台机器被五种方式投影**的结果。那台机器很简单:一个 agent 由参数权重与非参数脚手架构成,外加一个**更新算子**把某种学习信号持久地写回其中之一。

![自进化在能力阶梯上的位置:LLMs 到 Foundation Agents 到 Self-evolving Agents 再到 ASI](reads/img/dispatch-43-self-evolving-agents/orig-ladder.jpg)

*图 1 · 综述给自己定的位置。原图出自 Gao 等《A Survey of Self-Evolving Agents: What, When, How, and Where to Evolve on the Path to Artificial Super Intelligence》(TMLR 2026-01,27 位作者,arXiv 2507.21046),仓库 [CharlesQ9/Self-Evolving-Agents](https://github.com/CharlesQ9/Self-Evolving-Agents),Apache-2.0。注意右端:这份综述把自进化明确定位为通往 ASI 的台阶——这是一个强主张,本篇第 8 节回来检验它。*

五份综述,五种投影:

| 综述 | 主轴 | 特点 | 代价 |
|---|---|---|---|
| **Gao 等**(TMLR 2026-01) | What / When / How / Where | 四问近似正交,每问对应一个实际决策 | How 把"信号形式"与"优化器族"混在一起 |
| **Fang 等**(arXiv 2508.07407) | 四组件控制回路 | 唯一提出**规范性法则**:三定律 Endure > Excel > Evolve,严格分级 | 时机不是一等轴 |
| **Xiang 等**(厦大,TechRxiv) | 相对环境的位置:模型侧 / 环境侧 / 共进化 | 唯一顶层即编年史的分类 | "环境侧"成了大杂烩 |
| **Ren 等**(Schmidhuber 组,arXiv 2607.13104) | 更新目标 + 形式算子 | 最精确,只分两支 | 把"技能"设为正交构造,与他人冲突 |
| **微软研究院**(2026-07,约 300 篇) | Substrate × Pathway × **Pressure** | 唯一把"选择压来自谁"设为一等轴 | 排除多智能体互相适应 |

**分歧是实质性的,不是措辞。** 最典型的三处:

- **记忆放在哪。** Gao 归入 Context(What 的子类),Fang 设为单智能体优化支柱,厦大**拆成两处**(环境侧的动态经验演化 + 模块化架构演化下的记忆架构演化),Ren 视为脚手架分量 `m`,微软给它独立基质 `M`。
- **"共进化"指什么。** 厦大的共进化分支以**多智能体策略共进化**开篇;微软明确裁定"人工智能体之间的相互适应**不算**共进化,因为它不要求 H ≠ 0(人类参与)"。两者完全相反。
- **技能是什么。** Ren 把技能定义为"更新算子的一个可复用实例",**故意横切**所有人当主轴的基质维度;厦大把它当成环境侧的一个叶子节点。

微软是唯一给出**边界裁定程序**的(Π/A、Π/M、A/M、H 四类歧义case),而这份程序存在本身就是分歧实质性的证据。

## 2 · 最精确的那把刀:θ 与 Σ

![自我改进的形式化:A=(θ,Σ),Σ:=(p,m,T,g),左侧为基础模型改进,右侧为脚手架改进](reads/img/dispatch-43-self-evolving-agents/orig-theta-sigma.png)

*图 2 · 本篇最关键的一张图。原图出自 Ren 等(Schmidhuber 组)《Self-Improving AI Agents: A Survey》,arXiv 2607.13104,仓库 [selfimproving-agent/awesome-Self-Improving-Agents](https://github.com/selfimproving-agent/awesome-Self-Improving-Agents),**MIT**。左侧 FM 改进:`θ_{t+1} = IMPROVE_θ(θ_t; S_t)`,Σ 不变,按信号分三类——内生示范 `S≈D_t`、内生反馈 `S≈r_t`、外生经验 `S≈τ_t`。右侧脚手架改进:`Σ_{t+1} = IMPROVE_Σ(Σ_t; S_t)`,θ 不变,按分量分四类——提示词、工具、记忆、全脚手架。*

Ren 等给出的定义值得逐字保留:

```
A_t = (θ_t, Σ_t) ,  Σ_t := (p_t, m_t, T_t, g_t)
                       提示词  记忆  工具  控制逻辑
```

他们的关键动作是把**短暂的执行状态** `X_t`(KV cache、工作上下文,任务边界处重置)与**内在配置** `(θ, Σ)` 分开:**上下文内适应移动的是 `X_t`,不算自我改进;只有把变更持久写回 θ 或 Σ 才算**。微软的表述等价:`S^(t+1) = Φ(S^(t), E^(t) + H^(t))`,"下标 t 标记的是更新事件,不是墙钟时间……`S^(t)` 只在一次固化写回时前进"。

这把刀锋利在哪:**动 θ 是在固定决策过程上做标准策略优化;动 Σ 是在重塑策略所处的决策过程本身,因此在标准 RL 里没有对应物。**

> **与本站 D41 的接口(已更正)。** Ren 等的 `Σ=(p, m, T, g)`(提示词、记忆、工具、控制逻辑)与 D41 记录的 Prime Agent harness `H=(p, G, K, M)`(提示词、子代理、技能、记忆)在**同一个位置**上做切分——都把非参数脚手架形式化为一个与 θ 分离、跨任务持久的元组。但**两者不是同一构造,四个分量也不逐项对应**:Σ 有工具与控制逻辑而没有子代理,H 有子代理与技能而没有显式的控制逻辑槽位。核验中还查清了一条谱系:D41 引用的 Continual Harness(Karten 等,arXiv 2605.09998)与 Prime Agent 的 `/refine` 在关键语义上相反——前者第一步就重写系统提示词且每 50 步自动变异、无接受测试,后者明示**永不改写不可变的基础系统提示词**且带快照与回滚。两者是**同源谱系,不是同一系统**。可以保留的结论只有术语层面的那一条:Ren 等注意到社区越来越多地说 "harness" 而他们说 "scaffold",本站 D29/D41/D42 追踪的 harness 文献与这里的"脚手架改进"分支确实是同一批工作的两个名字。

## 4 · 模型侧:自己改自己,以及它为什么常常失败

![模型侧自进化:合成驱动的离线演化与探索驱动的在线演化](reads/img/dispatch-43-self-evolving-agents/orig-model-centric.png)

*图 5 · 模型侧的两个家族。同图 3 出处。左:合成驱动离线演化(SFT 型 / 离线 RL 型 / 参考型),特征是静态自举、知识精炼、泛化受限。右:探索驱动在线演化,分**纯自博弈(无人类数据)**与**人类数据引导的自博弈**,结构都是 Challenger 出题、Solver 解题的在线循环。*

### 推理时演化:三种机制,一个共同瓶颈

**并行采样**(Self-Consistency)采 m 条链取多数。它是**方差削减器而非偏差削减器**:当错误相关(系统性误读、位置偏置)时,所有样本会一致地错,投票只会放大。它同时是所有花哨方案必须在**等 token 预算**下击败的基线——而多智能体辩论在 9 次响应的等预算下只有 83.0%,朴素 self-consistency 是 88.2%。

**序贯自我纠错**(Self-Refine、Reflexion、CRITIC、SCORE)的关键区别在于**批评意见的信息来自哪里**。Reflexion 的评估器通常是**外部**二值信号(单元测试、环境成功)转成语言记忆;CRITIC 明确把输出路由过搜索引擎与解释器。这些有效。而**内生自我纠错**——模型无预言机地自评——是净负的:

| 设置 | 结果 | 必须一起读的限定 |
|---|---|---|
| GPT-4,GSM8K,两轮内生纠错 | **95.5 → 91.5 → 89.0** | **200 题随机子集**,温度 1,单次运行——这个降幅是 13 道题 |
| GPT-3.5,GSM8K,一轮 | 对→错 **8.8%** vs 错→对 **7.6%** | 全集 1,319 题;差值 −1.2 个百分点,**统计上不显著**(McNemar p ≈ 0.28) |
| GPT-3.5,CommonSenseQA | 75.8 → **38.1** | 作者自己归因于**选择题的选项切换偏置**,属 harness 效应而非推理退化 |
| Llama-2-70B,GSM8K | 62.0 → **36.5** | 四个模型均为 2023 年前后的非推理模型 |
| 同一循环但**给预言机** | 75.9 → **84.3** | 预言机决定何时停手 |

**这张表的效力有边界,必须说清**:「单调下降」只在 GPT-4 × GSM8K 这一格成立(同一批实验里 GPT-4 在 CommonSenseQA 上是 82.0 → 79.5 → **80.0** 回升,GPT-4-Turbo 在 GSM8K 上是 91.5 → 88.0 → **90.0**),而且换一个中性的批评提示词后降幅只剩 0.5 个百分点、即 200 题里的一道。稳健的结论是**负向且比较性的**——自评在任何一格都没有带来增益,并且在等 token 预算下输给并行采样(88.2 对 83.0)。原因是信息论上的:**如果模型能可靠分辨对错,它一开始就会给出对的答案**。早期论文报告的增益是把真值标签用来决定**何时停止**纠错,于是循环只动了本来就错的答案——那是预言机引导的筛选,不是自我纠错。Kamoi 等的 TACL 综述把这一点推广到整个文献。

机制上更细的诊断:GPT-4 只有 **52.87%** 的概率能找到 CoT 中第一个出错的步骤,但**告诉它错在哪**之后修复能涨 18 到 44 分——**缺的不是修复能力,是独立的错误信号**。

> **2026 年的一处反转值得记下。** 把逐字节相同的错误陈述从模型自己的 assistant 轮**改标**为 user 或 tool 轮,显式纠错率在 12 个模型-领域组合上跳升 **23 到 93 个百分点**。也就是说"LLM 不能自我纠错"里有相当大一部分是**聊天模板下对自己文本的谄媚**,而非认知上限。

**结构化推理**(ToT、GoT、Meta-CoT、PlanSearch)把搜索显式化,但打分者仍是模型本身,因此继承同一个验证瓶颈。PlanSearch 的真正贡献是诊断出**杠杆是多样性而不是深度**:在自然语言方案层面搜索而非代码层面,把 Claude 3.5 Sonnet 的 pass@200 从 60.6% 提到 **77.0%**。

### 训练时演化:零数据自博弈如何自造任务与奖励

离线合成一族(STaR、ReST、LMSI、Self-Instruct、SPIN、SPPO)是同一个循环——生成 → 过滤 → 在幸存者上 SFT——**只在过滤器上不同**。值得单独点出的是 **SPIN 不是零数据自进化**:它的判别目标要求偏好**人类** SFT 回答胜过自己的旧生成,所以它的不动点就是人类数据分布,**无法超越**。这一族普遍在 **n≈2 轮**达峰。

在线探索一族才是真的零数据。要造两样东西——**任务分布**与**奖励**——全部工程都在于各自如何接地:

| 奖励接地方式 | 代表 | 可信度 |
|---|---|---|
| **可执行器** | AZR(Python 解释器判定)、Self-Challenging(Challenger 必须同时产出验证函数) | 最高,奖励无法被幻觉 |
| **零和博弈** | SPIRAL(胜负定义上正确,对手是不断变强的自己) | 高,且不饱和 |
| **语料** | SPICE(Challenger 看得到文档、Reasoner 看不到,**故意打破信息对称**) | 中,引入外部信息 |
| **多数投票** | R-Zero、SQLM、TTRL | **最弱**,把推理时的自洽信号提拔成训练目标,错误因此永久化 |

课程接地则高度统一,都是**"可学习性"/前沿奖励**:当 Solver 的经验成功率接近 1/2 时奖励出题者(R-Zero 瞄准约 50% 不确定度,AZR 用 1 − 平均解出率)。这是**防坍缩装置**:只奖励难度,出题者会漂向无解噪声;只奖励可解,会漂向琐碎。

**真正阻止坍缩的东西比框架叙事窄。** 理论上自我改进是**锐化**(sharpening):它不能创造模型没有的信息,只能把概率质量集中到模型**已能验证**的序列上;可利用的量是**生成-验证差距**,有限且随预训练算力变化——**每个零数据循环都在跑赢一个正在枯竭的资源**。一项受控研究给出了更硬的结论:**严格的数据闸门(哪些被提议的任务准入训练)在所有奖励变体下都足以保证稳定,而一旦撤掉闸门,没有任何奖励设计够用**。

## 5 · 环境侧:冻结权重,改其余一切

![静态知识演化与动态经验演化的机制对照](reads/img/dispatch-43-self-evolving-agents/orig-exp-driven.png)

*图 6 · 环境侧的两大类。同图 3 出处。左:静态知识演化(Agentic RAG、推理驱动的深度研究),特征是补充世界知识、知识密集任务、泛化受限。右:动态经验演化,分离线经验编译、在线经验适配、终身经验优化三段,特征是**蒸馏抽象经验、逻辑密集任务、强跨任务泛化**。注意右侧第三格明确画出了 Write / Read / Update / Delete 四个操作——记忆是被 CRUD 的。*

这一支冻结 θ,把策略写成 `π(·|θ, S)`,S 是持久的非参数产物状态;"演化"就是在 S 上做搜索,而 LLM 既是优化器又常常是(不可验证的)奖励。

**记忆这一支的工程核心在写入侧,不在读取侧。** 难的是准入、改写与丢弃,不是相似度检索。表示上有一条清晰的阶梯:原始轨迹(Memento 的案例库)→ 原子事实(Mem0)→ 带链接的笔记(A-MEM 的卡片盒:关键词、标签、上下文描述、嵌入、链接)→ 蒸馏出的策略(ReasoningBank 的 {标题, 描述, 内容};ACE 的 playbook 条目)→ 概念(ArcMemo)→ 可执行技能(Voyager 的代码库)→ 潜变量(MemGen,完全不用文本)。

抽象层级是核心权衡,而且**经验上是双向的**:高层洞见跨域可迁移(六个编码基准平均 +3.7%),低层轨迹则会引发**负迁移**。

写入策略才是难的部分。Mem0 抽取事实后对最近邻的十条记忆发 ADD/UPDATE/DELETE/NOOP 工具调用;ReasoningBank 用 LLM 自评、无真值,一个提示抽成功策略、另一个从失败里抽"反事实陷阱"——**失败被当作一等信号**;SEDM 要求一条记忆只有在无环境 A/B 重放显示边际效用为正时才准入。

遗忘机制被普遍当作这一支的答案,**但本站核到的实现状态比论文叙述弱得多**,这里如实记录:MemoryBank 论文用艾宾浩斯指数衰减并在被召回时强化,而仓库里 `enable_forget_mechanism` 默认为 `False`、唯一的启动脚本把它硬编码为关闭,开启后还会 import 一个仓库中不存在的模块;其衰减式 `math.exp(-t / 5*S)` 按运算优先级解析为 `exp(-t·S/5)`,与自身文档注释相反——**强记忆反而衰减更快**;而且它的"遗忘"是随机删除,不是按效用。ACE 用增量 delta 更新加 helpful/harmful 计数,其 README 自述还会做确定性合并、去重与剪枝——但**本站核到代码一侧是另一回事**:Curator 提示词里写着「当前实现只支持 ADD 操作,不要输出 UPDATE / MERGE / DELETE」,`playbook_utils.py` 把这三个算子列在「TODO: 尚未实现」下,仓库里唯一的边界是一个作为提示词文本注入、代码中并不强制的 80,000 token 预算。**ACE 实际是严格追加的**,其论点本身也是反「收紧」的(grow-and-refine,明确为了打败两件事——"简洁性偏置"(摘要丢掉领域细节)与"上下文坍缩"(反复重写整段上下文等于递归地跑一个有损自编码器,细节因损耗而死));LightMem 把固化推迟到离线"睡眠时"批处理,使在线成本保持平坦(在线 token 最高降 106×/117×)。

**模块化架构演化**的区分点是**搜索算子**:ADAS 让元 agent 直接编写约 100 行的 `forward` 函数并把归档当种群;AFlow 用预定义算子(Generate/Review/Revise/Ensemble/Programmer)约束空间并跑 MCTS 变体;**GEPA 用自然语言反思做变异,并维护逐实例分数的帕累托前沿**而非单一全局最优——这正是它能以最多少 35 倍的 rollout 击败 GRPO 约 6 个百分点的原因:**一次语言反思比一个标量优势提取的比特数多得多**;Gödel Agent 的算子是"任意自编辑",包括改写那段改写代码的代码。

**拓扑演化**把 S 设为通信图:GPTSwarm 用 REINFORCE 优化连接概率,G-Designer 从变分图自编码器解出任务自适应拓扑,MaAS 更进一步让拓扑**逐查询条件化**(从"agentic supernet"采样),成本因此降到基线推理的 6–45%。

## 6 · 共进化:自适应课程其实是梯度信号保全装置

![四组件闭环:System Inputs、Agent System、Environment、Optimiser](reads/img/dispatch-43-self-evolving-agents/orig-loop.png)

*图 7 · Fang 等的四组件控制回路。原图出自 arXiv 2508.07407,仓库 [ANative-Lab/Awesome-Self-Evolving-Agents](https://github.com/ANative-Lab/Awesome-Self-Evolving-Agents),**MIT**。Setup → Execution → Feedback → Mutation → Refine 五条边闭合;Optimiser 的搜索空间含提示词模板、工具选择、LLM 参数与架构,优化算法含规则启发式、梯度下降、贝叶斯/MCTS/RL、学习型策略。这张图的价值在于给出"反馈从哪里进入"的统一词汇——提示词优化器、记忆管理器、工作流搜索器都是 Optimiser 这一个槽位的实例。*

共进化分两半,性质不同:**可扩展环境演化**主要是**供给**(造更多可执行世界),**自适应课程演化**才是真正的闭环——环境的输出分布是当前策略的函数。

**核心机制可以被精确说出来。** 每次 RLVR 训练都有一个隐藏量:采样到的提示中,rollout 组既非全对也非全错的比例。在 GRPO 式的组相对优势下,**全对或全错的组给出零优势,因此零梯度**。RLVE 把它命名为 **effective prompt ratio**,定义在**提示**而非 rollout 上——"rollout 给出非同一奖励、因而不被 DAPO 的动态采样丢弃的提示所占百分比"。它的消融是这一支少见的机制证据,但强度比通常转述的弱:

- **论文没有报告任何 EPR 数值。**本站更正:初稿写的「约 50–80%」在原文中不存在,全文只有 3.37%、0.49%、约 2% 与 τ_acc = 90% 这几个百分数;EPR 只以图 3 中一条无刻度标注的曲线出现,图注的措辞是"自适应难度保持最高的 effective prompt ratio"。
- 可核实的只有方向与两端:静态**低**上限区间的比例"最终掉到零",静态**高**上限区间"保持非零,但显著低于自适应"。
- **预言机那一档只到持平。**论文正文对 d ~ [0,20](其难度分布与同分布评测集重合,因而享有预言机优势)的原话是"即便没有这一优势,RLVE 也取得**相当或更优**的同分布性能"——是 comparable,不是碾压。多环境侧的"预言机"是一个覆盖式静态区间,且比的是性能而非 EPR。
- 这个消融只有**一个模型(Qwen2.5-7B-Base)两个环境**,单次运行、无种子与误差棒;它也没有把"维持可学习区间"与"难度单调上爬"分开。

所以自适应课程之所以有效,**是因为它们是梯度信号保全装置,不是因为教学法**。

代表结果(均为自报,设置见括号):RLVE 用 400 个可验证环境,在 1.5B 推理模型上六个基准平均 +3.37%,而继续原有 RL 只有 +0.49%——**但这不是受控对照**:两臂的任务分布、RL 算法、代码库与算力都不同,基线还是第三方(BroRL 团队)提供的 checkpoint,RLVE 方从未自己跑过它;算力方向对 RLVE 有利(约 1,100 对 3,600 H100 卡时),但也正因如此,这组数字能支持的是"更省",不是"环境数量带来增益"——论文真正的环境数量消融(C1 ⊂ C4 ⊂ C16 ⊂ C256)只报在留出的 50 个同族环境上,从未报在这六个基准上。DreamGym 在 WebShop/ALFWorld 上用**纯合成、零真实交互**匹配需要 8 万次真实交互的 GRPO/PPO;Environment Tuning 仅用 400 个训练实例把 Qwen2.5-7B-Instruct 的 BFCL V3 从 7% 提到 37%。

SPICE 给出了这一支**最干净的共进化动力学证据**:Reasoner 对**固定** Challenger 的通过率从 55% 升到 85%,而对**同步演化**的 Challenger 的通过率从 55% **降到** 35%——两个角色确实都在变强。

## 7 · 失效模式:打分者位于被打分者的下游

![三支路线各自的局限,以及共进化如何回应](reads/img/dispatch-43-self-evolving-agents/orig-co-evolving.png)

*图 8 · 综述自己承认的失效模式。同图 3 出处。左(模型侧):缺乏外部验证与低质数据、迭代中的误差累积、高概率过估计与高方差。中(环境侧):被动且有限的环境反馈(稀疏奖励)、静态环境与训练脱节、不可扩展的单任务环境。右(共进化):自适应难度调整、按需的定向反馈、可扩展多任务环境。**这张图的读法是从左到右的因果链——每一支的存在,都是前一支失效模式逼出来的。***

自进化是一个控制回路:提议、打分、接受或丢弃。**所有已记录的失效都是这三个箭头之一的失效**,而且几乎都来自同一个结构性事实:**在自进化系统里,打分者位于被打分者的下游**。

**① 打标机制与课程目标耦合,于是标签质量在训练分布上被设计着变差。** R-Zero 自己的论文给了一手数字:随着 Challenger 把题变难,多数投票伪标签的真实准确率 **79.0% → 69.0% → 63.0%**(Qwen3-4B-Base,每档 200 题,以 GPT-4o 为"完美标注者")。**本站更正**:初稿把这条序列读成"验证器衰减",这是错的——R-Zero **没有验证器**,标签是 Solver 自己 10 次采样的多数投票;而且同一张表显示,在任何**固定**题集上打标器是**变好**的(Solver-45 在 D_15 上 61.0 对 59.0,在 D_45 上 50.5 对 47.0)。下降的那条序列量的是**评测分布在变难**,不是打标器在变坏。

真正的机制反而更尖锐,而且是**设计进去的**:Challenger 的不确定度奖励 `1 − 2|p̂ − 1/2|` 在 p̂ = 0.5 处取最大,过滤器只保留 10 次采样中有 3 至 7 次一致的题——**课程目标精确地把训练分布推到多数投票最不可靠的那个点上**。所以这不是"验证器会累",而是"出题目标与打标机制共用同一个模型的信念,且前者的最优解正是后者的最差工况"。作者还明确否认标签噪声是坍缩的主因(0.6B 在标签准确率 70.6% 时就开始退化,4B 到 48.8% 仍能撑住),并指向纯自造数据导致的模型坍缩。

Single-R-Zero 消融(出题者与解题者**共享参数**)的数字成立:伪标签准确率在每一步都更差(63.4% 对 71.0%,第 45 步 32.6% 对 48.8%),且在第一个检查点就达峰。**但本站更正**:初稿称它测出了"评估者-被评估者相关性"——该消融的两个臂**都**从同一基座初始化,它隔离的是**训练期的参数共享**,不是评估者与被评估者的相关性本身。后者另有独立证据:GRPO 组内验证器错误相关系数 0.530,于是 8 条补全的组**有效样本量只有 1.70**。

**② 裁判可以被刷到与真值脱钩。** 用无参考 LLM 裁判在 GSM8K 上做自博弈,裁判通过率从 **0.72 涨到 0.94**,而隐藏锚点测出的**真实准确率始终停在 0.20**;而且这些利用手法**跨裁判族与规模迁移**,严格的三裁判集成仍然接受 55%。裁判打的是**合理性,不是正确性**。

**③ 接受规则把噪声洗成进展。** Agent 评测本身就噪声大(单次 pass@1 波动 2.2–6.0 个百分点,要检出 2% 的效应约需 9 次运行),而自进化循环反复用同一个开发集测试候选——这是**不受控的自适应多重检验,agent 在对自己做 p-hacking**。在贪心的"留出集涨了就留下"规则下,**30–42% 的提交是假的,10–33% 实际有害**;而当**根本没有真实改进可得**时,循环每次运行仍会提交 13–21 个虚假变更。

**④ 失进化(misevolution)不是加了几步的奖励攻击。** 在**没有对手、也没有参数更新**的情况下,安全性会沿全部四条演化路径退化:仅仅是记忆累积,就让一个 Qwen3-Coder-480B agent 的拒答率从 **99.4% 掉到 54.4%**;为 HumanEval 准确率做 AFlow 工作流优化,把拒答率从 36.3% 压到 **5.6%**,同时把 RedCode-Gen 的攻击成功率从 54.4% 抬到 **83.1%**。

**⑤ RLVR 的 pass@k 收缩是真的,但被过度解读。** 一次可审计的独立复现(每题 128 次采样、500 道 MATH500、4 个种子)确认了 pass@128 上 **−3.20 个百分点**(95% CI [−5.00, −1.40])。机制是 KL 正则的策略梯度最大化**单样本**奖励,对覆盖度无所谓,熵在约 200 个 GRPO 步内几乎耗尽。但这个指标本身有争议,而 ProRL/QuestA 在长时间训练配合参考重置下报告了扩张。**诚实的状态是两阶段观点:利用会收缩边界,长时间探索可能扩张它。**

## 8 · 评测:等预算对照下,演化打不过并行采样

这一节是本篇最冷的部分,也是最该被记住的部分。

**先要说清测的是什么。** SEAGym 的形式化最干净:一次 agent 快照是 `A_t = (M, H_t)`——**固定**的基座模型 M 加可变的 harness 状态 H_t(提示词、记忆、工具、中间件、运行时状态、模型-工具交互循环)。**如果 M 冻结,任何分数变化都不是模型能力,而是由 LLM 执行的 harness 工程。**这一句就消解了大量"自进化"修辞。

**决定性的对照,几乎没人做:把同样的 rollout 预算给任务本身的推理时搜索,而不是给 harness 搜索。**《Rethinking the Evaluation of Harness Evolution for Agents》在 89 个 Terminal-Bench 2.1 任务上、每题五次 rollout 做了这件事:

| 方案 | pass@1 |
|---|---|
| **朴素并行采样** | **72.3** |
| harness 演化 | 67.4 |
| 并行采样(有测试可用时) | **86.0** |
| harness 演化(同上) | 75.8 |

而当作者划出真正的 45/10/34 训练/验证/测试划分后,**演化后的 harness 得 68.3,初始 harness 得 67.7——在误差内**。

机制很朴素:两种做法买的都是对同一批任务的相关尝试,但 **best-of-N 当场兑现收益,演化却必须把收益压缩成可迁移的产物、并在推理时再付一次**。公平地说,演化的辩护是**摊销**:演化后的 harness 是可在未来任务上复用的固定成本,所以诚实的比较需要一个**生命周期分母**(多少未来任务才能摊平演化成本),而且 rollout 对齐**不等于** token、美元或延迟对齐。另一项研究 HARNESSEVO 在 ALFWorld 上做等预算对照,得到 0.657 对 0.642(stock harness 与扁平字符串演化),**无显著增益**,并把原因命名为"预算分割陷阱"。

**密封评测把头条数字打回原形。** RSI-Exam 让 agent 对着可见集迭代 12 小时,然后把提交的产物在全新容器里对**密封集**重放一次——"不能迁移的改进一分不得"。一次有记录的 10.5 小时运行中,可见集均值从 **0.10 爬到 0.63**,隐藏集只从 **0.13 动到 0.26**。HarnessDev 在 630 个未见 SWE-Pro 任务上评分:反馈方向与留出方向**在 64 次版本切换中只有 34 次一致(53.1%,相当于抛硬币)**,可见增益 13.9/13.4/8.8 分对应的留出增益只有 1.43/3.17/2.70,**9 个被声明的最终版本里只有 2 个真是留出最优**。

SEAGym 自己的数字说明了多视图评测的价值:TF-GRPO 与 AHE 在验证集上涨幅**完全相同**(都是 +17.1 分);但在留出同分布上 AHE 保住 +9.1 而 TF-GRPO 只剩 +3.6;在 OOD 上 AHE 涨 +6.3 而 TF-GRPO **倒退 2.5**。**单曲线报告会把这两个方法判成一样好。**

> 回到图 1 的强主张:综述把自进化定位为通往 ASI 的台阶。以本节的证据看,更准确的说法是——**自进化目前被可靠证明的,是一种在给定任务分布上把推理时搜索结果摊销成可复用产物的方法,而这件事的收益在等预算与密封评测下尚未稳定跑赢直接搜索。**

## 9 · 产业:所有已出货的自进化都写文本,不写权重

![从 MOP 到 MOA 到 MAO 再到 MASE 的历史路径](reads/img/dispatch-43-self-evolving-agents/orig-path.png)

*图 9 · 产业路径。同图 7 出处,**MIT**。模型离线预训练(2018–19 BERT/GPT-1)→ 模型在线适配(2020–22 GPT-3/LoRA/Prompt-Tuning/InstructGPT/RLHF)→ 多智能体编排(2023–24 MetaGPT/AutoGen/LangGraph/CrewAI)→ 多智能体自进化(2024–25 ADAS/AFlow/MIPRO/EvoFlow/MASS/EvoAgentX)。*

这一角度最吃重的事实是**架构性的,不是意识形态的**:一个生产 agent 就是**冻结解码器前面的一条上下文装配流水线**。每一轮,harness 把系统提示、工具 schema、技能元数据、记忆文件、对话历史与用户请求拼成一个字符串,模型是这个字符串的纯函数。所以学到的改进只有两个地方可放——**权重里,或字符串里**。产业选了字符串,原因是机械的:

1. **前缀缓存让上下文成为便宜面、权重成为昂贵面。** 一套权重服务所有租户、跨请求复用 KV cache,是前沿模型服务经济学的基础。**按客户的权重增量破坏这个假设,按客户的文件不破坏**——它只改变前缀的一个后缀。Anthropic 的 Skills 设计把这点量化了:技能元数据常驻约 100 token,SKILL.md 正文仅在触发时加载(5k token 以内),打包资源"在访问前为零"。Nous Research 给演化技能定的护栏里直接写着"**缓存兼容性——不得在会话中途变更**"。
2. **文本产物是唯一能 diff、审阅、门控与回滚的单位。** A-Evolve 把这一点做成契约:"所有可演化的 agent 状态以标准目录结构存在文件系统上","每次被接受的变异都打 git tag(evo-1, evo-2, …),提供完整审计轨迹",回退用 git。**你没法以同等信心 git-revert 一次 LoRA 合并**,更没法把它拿给合规审查看。
3. **在真实团队拥有的 rollout 预算下,反思式文本优化胜过 RL。** 这是 GEPA 的核心论点:RL"把执行轨迹坍缩成一个标量奖励",而 GEPA"用 LLM **读**完整执行轨迹——错误信息、profiling 数据、推理日志——来诊断候选**为什么**失败并提出定向修复"。实测差距约 **35 倍样本效率**:100–500 次评估对 GRPO 的 5,000–25,000+ 次。如果你的环境每次 rollout 要花掉数美元与数分钟,500 次是一顿午饭,25,000 次是一个季度。

**收益是真的,但它们是 harness 收益,而且可迁移。** A-Evolve 用冻结的 Claude Opus-4.6 把 MCP-Atlas 推到第一(79.4%)、Terminal-Bench 2.0 上 +13.0 个百分点,且"零小时人工 harness 工程";更能说明问题的是,他们把在 TB2 上学到的 harness 与技能"**直接移植**"到另一个编码 agent 上,把它从 67.8% 抬到 72.9%。Live-SWE-agent 从另一头印证:一个**最小的开源**脚手架在运行时自己改写工具,让 Opus 4.5 在 SWE-bench Verified 上达到 79.2%,"非常接近 Anthropic 内部人工精调的脚手架"。

**代价有三个。** 一是**能力上限**:上下文编辑装不进基座模型没有的技能——A-Evolve 自己的 ARC-AGI 只从 10.1% 动到 12.3%,而 SkillsBench 涨了 15.2 个百分点(后者是模型本来就会的技能检索任务)。二是**上下文预算成了新瓶颈**:Claude Code 的自动记忆只加载 MEMORY.md 的前 200 行或前 25KB,学到的知识现在要和任务争抢同一份稀缺资源。三是**这个循环并未自主闭合**:Nous 只上线了五个阶段中的第一阶段("所有变更走人工审阅,绝不直接提交"),Anthropic 的 Skills 文档承认"目前没有内建方式来运行这些评测"。

## 10 · 对 RL-on-NPU 的含义

自进化循环按算力形态分成三段,昇腾的就绪度差别很大。

**① 推理时演化是解码受限的,而且已经完全支持——这一支是免费的。** 并行采样、序贯自我纠错、结构化推理都不碰权重,成本是 prefill + N × decode,受 HBM 带宽与 KV 容量约束。决定性的优化是**前缀复用**:N 个样本共享同一前缀,自我精炼链每轮重读自己的历史。vLLM-Ascend 把 Automatic Prefix Caching、Chunked Prefill、ACL Graph 三项都标为 🟢 Functional——**ACL Graph 在 NPU 上比在 GPU 上更要紧**,因为自我精炼是一长串**短**解码,主导成本是每步的主机侧启动开销而非 FLOPs。

**② 在线训练演化就是训推共卡问题,而昇腾要付一笔具体的税。** 自博弈循环交错 rollout 与权重更新。单节点上用的是**共卡**,原语是 vLLM 的 sleep mode,vLLM-Ascend 实现了它;但文档明确写出代价:`rl_config.sleep_mode_extra_cleanup` 还要"等待挂起的流水线并行发送、同步 NPU、**销毁 HCCL 进程组**",而 `wake_up()` 后"必须在模型状态恢复后**重新调用 `capture_model()`**"。**于是昇腾上每一次 rollout↔train 切换可能要付一次 HCCL 集合通信重初始化加一次 ACL graph 重捕获**;CUDA 上对应的 graph 重捕获更便宜,NCCL 组也不被拆掉。这正是 MindSpeed-RL 的训推共卡改为让训练器常驻、生成期间把优化器状态与梯度卸载到主机 DRAM 的原因——**用 PCIe/主机带宽换 HCCL 抖动**。

好消息是**异步这条逃生口已在昇腾上验证**:verl 的 `fully_async_policy` 与 `one_step_off_policy` 都出现在 verl 的 Ascend 模型/算法表里并附 NPU 启动脚本;AReaL 实测其异步 NPU 路径两个 epoch 用 4.3 小时,而 verl 同步版一个 epoch 要 6.8 小时,OOD 准确率相当。

**③ 环境侧演化分成便宜的检索态与昂贵的长上下文态,而且有一条明确的设计规则。** 若系统是检索优先的(如 ReMe 把记忆存成 Markdown、用 BM25 做行级片段检索,"不把整个知识库load进 agent 上下文"),负载在 CPU 侧,与 NPU 无关。若是上下文优先的,每次 rollout 都变成长 prefill 作业,约束变成 KV 容量与 prefill 吞吐。此时昇腾上的设计规则是精确的:

> **把演化中的记忆放成稳定前缀,让自动前缀缓存命中;把逐任务检索放在它之后。**
> 逐任务检索到的记忆会每轮改变前缀,**彻底击穿 APC**,把一次可摊销的 prefill 变成反复的 prefill。

**④ 这让 D42 的结论更尖锐。** DeepSeek-V4.1-Flash 的 890 字节/token 全局 KV 是**架构属性**,vLLM-Ascend 逐字复述了这一数字。但 910B 档硬件上的服务路径不是原生那条:原生混合 MXFP8/MXFP4 权重路径只列在 "Ascend 950 Products" 下,A2/A3 上验证的配置是 **W8A8**(ModelSlim INT8),需要两台 Atlas 800 A3 或四台 A2 **共置**部署,PD 分离在 A2/A3 支持矩阵里标 ❌。量化指南给出的通则是:在 950 以外的昇腾代次上,FP8 块缩放"在加载时被解析成模型 dtype 并由 BF16 matmul 服务……按大约两倍权重显存来规划"。**所以廉价 KV 的长上下文底座,正是记忆型自进化在昇腾上最需要、而目前恰恰还没兑现的那一块。**
