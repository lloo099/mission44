DeepSeek-V4.1-Flash 精读:因果编码器-解码器、CSA2 跨层复用与 FP4 KV——890 字节的账怎么算

技术报告的标题就是全部论点:《Pushing the Limits of KV Cache Compression》。V4.1-Flash 不是更强的模型,是把 KV cache 从"算力问题"改写成"存储与通信问题"后给出的一整套解——CED 让 prefill 只跑半个网络,CSA2 让 40 层里只有 4 层写全局 KV,FP4 把每条 KV 压到 288 字节,三者相乘得到 890 字节/token。本文把 D42 的十三节逐一拆开:每节先给"不看这份报告时的朴素直觉实现",再给报告与源码里的实际做法,最后写清差在哪、官方是否给了证据、对 RL-on-NPU 意味着什么。全文有三处对流传说法的更正。

00全景与读法

DeepSeek-V4.1-Flash 于 2026-09-10 发布(MIT,552B 主干 + 196B Engram,原生多模态,1M 上下文)。它的技术报告把先前稀疏注意力工作的后果说得很直白:算力降下来之后,持久存储与数据搬运成了瓶颈。于是这一代的目标不是分数,是每 token 的字节数。三刀叠加:CED(因果编码器-解码器,解码器全局 KV 由第 20 层隐状态投影,prefill 激活 8B 对 decode 16B)、CSA2(Full / Reindex / Reuse 三模式静态分配,40 层只 4 层写全局 KV)、FP4 main KV(E2M1 + 每 16 通道 E4M3 scale,288 字节/条)。官方数字 890 字节/token,本站按 FlashMLA 与 SGLang 的字节布局逐项复核,精确吻合;叠加 SWA Bounded Replay 后持久 KV 降到 V4-Flash 的 1/8。

本文的读法

每一节固定三段:朴素基线(左栏,灰)——不看这份报告、按直觉搭一个长上下文 MoE 会怎么做;它的做法(右栏,橙)——技术报告、模型卡、配置文件与 SGLang / vLLM / FlashMLA 源码里的实际做法;差在哪(下方色块)——差异的实质、官方是否给了理由或证据、对 RL-on-NPU 的含义。数字按来源分三类:第三方 独立测量或多方一致;自报 DeepSeek 或其他厂商口径;推断 本站分析或按公开布局的重建。

贯穿全文有两条线索。其一是三个乘法维度:条目多大(GQA → MLA → 单头 MQA-512)、多少 token 合成一条(序列压缩比)、多少层各存一份(跨层复用)——CSA2 是第一个同时覆盖三维的设计,FP4 再乘一个精度因子。其二是harness 即分数的双侧证据:厂商自己印出了同一模型在八种 scaffold 下 8.7 分的极差,第三方 Vals.ai 用中立 harness 重跑头条基准低了 16 分。

三处对流传说法的更正

① V4-Pro 退役已被撤回。 09-10 公告"09-14 起 deepseek-v4-pro 路由到 V4.1-Flash",09-11 DeepSeek 宣布"继续为 V4 Pro 提供 API 服务,计费方式不变"。本站 09-11 转述的是初始公告,以此更正。② SWE-bench Verified 79.0 与 LiveCodeBench 91.6 是 V4-Flash 的数字,V4.1-Flash 的厂商表根本没有这两行;HMMT 2026 的 94.8 同样属于 V4-Flash。③ 总参数不是 552B:552B 是主干,另有 196B Engram 条件记忆,含 DSpark 专家的 checkpoint 约 763B、511 GB。

01问题陈述:agent 负载下,KV cache 是存储与通信瓶颈

报告开篇:先前的稀疏注意力(V3.2 的 DSA、V4 的 CSA/HCA)"显著降低了长序列处理的计算成本,使持久存储与数据搬运成为日益突出的瓶颈"。V4 的 KV 分两类:全局 KV(main KV + indexer K)随序列增长、受 HBM 约束;持久 KV(为前缀复用而落盘)受 SSD 与主机内存约束;I/O 与互连带宽再限制缓存迁移。窗口固定的 SWA KV 不随长度增长,序列足够长时全局 KV 主导运行时开销。

朴素基线

长上下文降本 = 稀疏注意力省 FLOPs。KV cache 照存,靠更大的 HBM 与更多的 SSD 解决容量,靠前缀缓存命中率解决成本。

它的做法

把目标函数换成每 token 字节数:全局 KV 压到 890 字节(约 V4-Flash 的 1/4),持久 KV 压到 1/8。自报 手段是架构、缓存精度、部署策略的联合优化,宁可接受近似重建与选择错误的风险。

差在哪差异在瓶颈的重新定义。官方给的证据是部署侧的观察(V4 部署里 SWA KV 占持久缓存近半、全局 KV 需 72 小时保留),不是理论推导。对 RL-on-NPU 的含义:推断 国产卡的单卡 HBM 与互连带宽恰是两处硬约束,一个以字节数为目标函数的架构比以 FLOPs 为目标的更贴近这类硬件的瓶颈。

02先看 V4 基座:V4.1 改的是什么

V4.1 的全部增量建立在 V4 的一套不寻常设计上,SGLang 主线的 deepseek_v4.py 与配置类给出最可靠的读法:单 KV 头 MQA(num_key_value_heads = 1,head_dim = 512,64 个 query 头共读同一个 512 维向量,既当 K 也当 V,输出上再乘共轭 RoPE 抵消位置泄漏);低秩 Q 与分组低秩 O;CSA / HCA 逐层 compress_ratio ∈ {0, 4, 128};每层 SWA-128 加注意力 sink;mHC 超连接(hc_mult = 4,20 步 Sinkhorn);前 3 个 MoE 层哈希路由;sqrtsoftplus + noaux_tc 路由。SGLang 内存池断言 V4 的 KV 为 584 字节/条(448 FP8 + 64 × 2 BF16 RoPE + 8 字节 scale)。

朴素基线

V4.1 是 V4 的增量版:同架构、更多数据、微调后训练。压缩比 4/128 的 CSA/HCA 交替是 V4 的招牌,理应保留。

它的做法

HCA 整体取消,CSA 换成压缩比更小(2 与 1)的 CSA2,把省下的空间用在层维度上;transformers 以新模型类型 deepseek_v41 注册,vLLM 配方称之为"与 V4 分叉的兄弟"——自报"新架构家族中最小的模型"。

差在哪差异在压缩发生的维度:V4 靠序列维度的重压缩(128×)换 KV 体积,V4.1 靠层维度的复用(4/40 层写 KV)换,序列压缩反而放松到 2× 与 1×。推断 这解释了为什么 D05 担心的"128× 丢 token 级细节"在 V4.1 的谱系里消失了——它没有 128× 的层;但代价转移到了"19 个解码层共读一份 512 维潜变量"这个新的容量瓶颈上。

03第一刀 CED:解码器的全局 KV 从编码器投影

报告 §2.2 的动机:agent 工作流中频繁的工具调用产生大量 prefill,KV 未命中时开销严重;设计受 YOCO 启发。核心是一条公式:对解码器(l > 20),全局注意力的 KV 不由本层 H_l 推出,而是用逐层投影矩阵直接从第 20 层隐状态 H_{L/2} 投影——C_l = H_{L/2} · W_l^KV,Z_l = H_{L/2} · W_l^Z。结论直接:prefill 阶段只需计算前一半的层。但 SWA 保持逐层计算:局部 K/V 仍来自本层 H_l,"有效增加了局部 KV 生成的计算深度"——CED 只折叠全局分支,局部分支保留 40 层深度。

复杂度:O(N × L) → O(N × L/2 + n_win × L/2) ≈ O(N × L/2) // N 为提示长度,L = 40,n_win = 128 精确重建解码器 SWA KV 需重放的 token 数:L/2 × n_win = 20 × 128 = 2,560 有界重放实际重放:n_win = 128 // 状态为近似;后训练中模拟同一重放做适配
朴素基线

要省 prefill 就用 YOCO:下半网络算 KV,上半网络交叉注意力读它,prefill 提前退出。或者用 T5 式编码器-解码器,编码器双向以获得更好的表示。

它的做法

编码器必须因果:第 i 个 token 的编码器状态与投影出的 KV 只依赖 ≤ i 的 token,所以前缀缓存只依赖全局 KV、追加后缀时"无需重算或覆写",分块 prefill 与多轮追加成立,整个网络照常按下一 token 预测训练。与 YOCO 的差别:无交叉注意力模块,同一条流上的自注意力;SWA 分支逐层保留。

差在哪差异在"因果"二字的工程后果:T5 式双向编码器会在每次追加时让全部缓存作废,与前缀缓存不相容。官方对 CED 本身没有独立消融——"保持与基线相当的性能"是在 CSA2 与 FP4 同时变化下的整体表述;有界重放的证据是 第三方 SGLang 的 AIME 2026 pass@1 开关重放均为 453/480,以及 自报"负面影响可忽略"。推断 对 RL 的含义在 §14:有界重放使 prompt 的 logprob 与隐状态不可精确复现,训练侧必须模拟同一近似。

04第二刀 CSA2:三模式、四个 KV 源层、一个候选池

每个 CSA2 层被静态指派一种模式,三种模式下每层都算自己的 query 与 SWA KV,区别只在如何获得 main KV、indexer K 与 Top-K 索引。Full:自算 main KV,由它投影 indexer K,自己的 indexer Q 打分选新的 Top-512。Reindex:复用最近 Full 层的 main KV 与 indexer K,但用自己的 indexer Q 重新打分、选新 Top-512——缓存共享不变、选择可逐层变化。Reuse:复用 main KV 与最近 Full 或 Reindex 层的 Top-K,不算 indexer Q、不评分。当 CSA2 与 CED 叠加,解码器中被指派 Full 的那一层用第 20 层隐状态算全局 KV。

生产模型的层拓扑(配置文件): compress_ratios = [0, 0] + [2] × 18 + [1] × 20 // + [0, 0, 0] 给 3 个 DSpark 层 kv_source_layer_ids = [2, 8, 14, 20] // 只有 4 层写全局 KV index_source_layers = [2, 8, 14, 20, 24, 28, 32, 36] // 8 层跑索引器 candidate_source = 20 · 2048 blocks × 8 = 16,384 候选 · index_topk = 512 · sliding_window = 128
朴素基线

每层各自压缩、各自索引、各自存 KV。层间独立,便于训练与实现;KV 体积随层数线性增长,索引计算随层数与上下文长度双线性增长。

它的做法

4 层写 KV、8 层跑索引、27 层只按继承的索引取数;解码器的 Reindex 层只在 16,384 位置的候选池内打分。自报 Reuse 模式的层 prefill 只 15 个 kernel、decode 11 个。压缩器同时简化:去重叠、去 APE、indexer K 由 main KV 投影。

差在哪差异是把层维度当成可压缩的维度。官方给的可行性证据是间接的:报告引 IndexCache、YOIO、HySparse 三篇前驱;第三方 IndexCache 测得相邻 DSA 层的 top-k 重叠 70% 至 100%,是"复用索引损失可控"的旁证,但不是本模型的数据。Reuse 对 Reindex 的质量差、候选池召回率,报告未量化。推断 对昇腾的含义:模式是编译期已知的静态信息,比 V4 的 CSA/HCA 交替更易做整图优化。

05第三刀 FP4 main KV:存储用低精度,计算不用

报告 §2.4.4 先划清一件事:V4 已用 QAT 把索引器的 Q/K 做成 FP4,那是为了加速索引计算;V4.1 把 QAT 扩展到 main KV,这里 FP4"减少存储而不是加速矩阵乘"——缓存值在注意力前先反量化,所以可以选更准的格式,而不要求硬件原生支持该格式的矩阵乘。格式选 E2M1 + 每 16 通道一个 E4M3 scale,"遵循 NVFP4 但省略其第二级全局 scale"。省略的理由是算术:格式上界 448 × 6 = 2,688;RMS 归一化后 512 维潜变量的 L2 范数至多约 √512 ≈ 22.6,RoPE 保范;训练中观测到的最大幅值约 10。上界比需求高两个数量级。QAT 在后训练引入;RoPE 之后量化;SWA KV 保留 FP8"因其对量化敏感"。

朴素基线

KV 量化 = 训练后量化(KIVI / KVQuant 一类),逐通道或逐 token 校准,接受一点精度损失;或者等硬件原生 FP4 矩阵乘,把注意力也算在低精度里。

它的做法

训练期让模型学会容忍(QAT),存储用 FP4,计算前反量化回高精度。两种 FP4 布局并存:indexer K 用 OCP MXFP4(E2M1 + 每 32 个值一个 UE8M0 scale,128 维 → 68 字节),因为它要参与索引器的低精度点积、选硬件通用格式;main KV 用 NVFP4 微块(E4M3 scale、每 16 个值,512 维 → 288 字节),因为只是存储、可以更准。SGLang 与 vLLM 都实现了这两套字节数。

差在哪差异是把"存储精度"与"计算精度"分开,这一点几乎没有报道指出。官方证据是定性的:自报"边际性能退化"、"无可测的精度下降"、"RoPE 前量化只带来边际改善";没有 FP4 对 FP8 的量化消融表。对昇腾的含义在报告原文里:"保持跨硬件平台的兼容性"——推断 昇腾侧只需 E2M1 → BF16/FP8 的反量化核与 288 字节页布局,不依赖 FP4 tensor core;需要参与低精度点积的 indexer K 用的是硬件通用的 MXFP4。

06890 字节的账

官方只给结论:全局 KV"始终在 HBM"的占用降到 890 字节/token,约为 V4-Flash 的 1/4。本站按 FlashMLA README 的 V4.1 字节布局(FP4 main KV 288 字节 = 256 字节 E2M1 数据 + 32 字节 E4M3 scale;indexer K MXFP4 68 字节)与 §4 的层拓扑逐项复核。

每条全局 KV(Full 层) = 288 (FP4 main KV) + 68 (MXFP4 indexer K) = 356 字节 编码器 3 个 Full 层,压缩比 2: 3 × 356 / 2 = 534 字节 / 原始 token 解码器 1 个 Full 层,压缩比 1: 1 × 356 / 1 = 356 字节 / 原始 token 合计 = 890 字节 / 原始 token // 精确吻合;SGLang 团队给出同一恒等式 两个基线: V4-Flash ≈ 21 × (584 + 68) / 4 + 20 × 584 / 128 = 3,514.25 字节 // 比值 3.95×;SGLang 表 3,514 DeepSeek-V1 = 2 × 95 层 × 8 KV 头 × 128 × 2 字节 = 389,120 字节 // 389,120 / 890 = 437.2,与图 1(b) 的 437 吻合
叙事怎么说

"KV cache 压缩 437 倍",一个模型把上一代的 KV 砍到四分之一。

证据是什么

890 可以从公开字节布局与层拓扑精确重建,437 与 3.95 两个比值也能复核。但 890 是逻辑大小:不含 SWA KV(FP8,每层 128 位置)、压缩比 2 层的待配对状态、页对齐填充(FlashMLA 按 512 字节倍数分页)。第三方 SGLang 团队明确提醒实际 HBM 用量有别。V4-Flash 的 3,514 来自 SGLang 而非报告正文(图 1(b) 是图片)。更要紧的是 890 假设 FP4 存储:FlashMLA 的 V4.1 稀疏解码核只支持 SM100,退回 FP8 主行(528 B)与 FP8 indexer K(132 B)后同一层拓扑给出 (528 + 132) × 2.5 ≈ 1,650 B,第三方 一个运行中的 SGLang FP8 部署实测 1,670.75 B/token。

本站判断890 与 1,670 之间差的不是架构,是部署精度——而 SGLang 与 vLLM 都验证了 8 × H200(Hopper,非 SM100)。DeepSeek 自家机队实际有多大比例跑在 FP4 上,无公开信息。除此之外,这笔账最值得带走的是它揭示的分工:解码器 19 层对全局 KV 的贡献为零,整个解码器的全局视野是每 token 一条 512 维 FP4 潜变量。这是一个很强的容量瓶颈,由 Reindex 模式与层级索引器部分补偿——LongBench-V2 基座回退 6.3 分是目前唯一一处公开的负面信号。

07部署:持久 KV 降到 1/8 的机制

V4 的部署里 SWA KV 占持久 KV 容量近半,因为多轮会话与重生成需要在提示末尾与输出末尾恢复状态。但它的访问模式与长保留策略不匹配:全局 KV 有长尾复用,SWA KV 只在活跃会话内分钟级的窄窗口里被复用。V4 报告的 Zero SWA Caching(不存、缺了精确重算 L × n_win 个 token)"在生产部署中成本过高"。V4.1 的答案是只重放最近 128 个 token 并把 SWA 截断在重放段内,接受近似状态。两个应用面:Encoder 侧让前缀缓存只依赖全局 KV,SWA KV 可以不再持久化;Decoder 侧让 prefill 在编码器处结束。

朴素基线

前缀缓存把全部 KV(含 SWA)落盘;命中即恢复;缺失则从头 prefill。存储按最长保留策略配置。

它的做法

全局 KV 持久化(SSD,≥ 72 小时);SWA KV 进每机 10% DRAM 的分布式池(分钟级 TTL,过期即回收);缺失时有界重放 128 个 token。第三方 SGLang dsv4.1 分支实现了解码器侧重放:第 0 至 20 层跑全部 token、第 21 至 39 层只跑每请求最后 128 个,prefill 吞吐 1.56×(8 × H200)、1.37×(4 × GB300);vLLM 主线目前仍跑全 40 层。

差在哪差异是按访问模式分层存储,这在数据库里是常识,在 KV cache 管理里是第一次被写进模型架构的报告。代价被官方写明:后缀的全局 KV 与 SWA KV"依赖缓存命中位置、跨位置不逐位相同";SGLang 已声明 prompt logprobs 不可用、拒绝确定性推理。推断 对 RL 训练的含义:on-policy 的训推一致性要求训练侧模拟同一重放,报告正是这么做的("train-aware adaptation")——推理侧的近似必须被训练侧看见。

08其余组件与训练

Engram 条件记忆(196B):第 1 与第 14 层,按 token 的 n-gram(阶 2 至 4)哈希查表,8 个哈希头 × 256 维,每表约 3.84 亿条,FP8。DSpark:3 个 Transformer 块的草稿器一次前向给出 5 个草稿位置,Markov 头建模草稿间依赖,置信度头预测各位置接受概率,调度器按引擎吞吐曲线为每请求动态选择验证长度;在预训练后单独训练、主干冻结,后训练期继续训但不把梯度传回主干。Single-Pass mHC:混合系数后移一块,残差更新、系数预测与混合融合为一个 kernel,激活流量 (4n + 4)d → (2n + 2)d。head-wise Muon:Query 权重按头拆分后做 Muon 更新,报告称该优势在 GLM 5 与 Kimi-K3 中亦得到验证。

训练:45T 多模态 token,批 100.6M,学习率 2.6e-4 至 28T、余弦降至 2.6e-5 于 40T、平稳到 45T;稀疏注意力从头在 64K 上训练,不经稠密预热;34T 处扩到 1M。基座以 1/3 总参数与 1/4 激活参数取得与 V4-Pro-Base 相当的能力:MMLU-Pro 74.1(V4-Pro 73.5)、HumanEval 79.4(76.8)领先;SimpleQA-Verified 42.3 对 55.2、LongBench-V2 45.2 对 51.5 落后。后训练"不引入算法创新",SFT → RL → OPD 沿用 V4,变化全在数据管线;可连续控制的推理努力 1 至 100,API 的 low / high / max 对应 50 / 75 / 100;25 → 100 时八项推理平均 67.1 → 76.3、DeepSWE 66.0 → 74.2、TB 2.1 82.4 → 90.6,输出 token 约 2.5×——所有头条数字都是 max 档的数字。

朴素基线

新一代旗舰 = 新的 RL 算法或新的奖励模型;投机解码用 MTP 与主干联合预训练;参数全部在主干里。

它的做法

自报 后训练无算法创新;196B 参数放在主干之外的查表里(Engram),激活时不算入 8B/16B;草稿器与主干解耦训练以便随策略演进而不污染主干;推理努力做成连续标量并以指数 token 惩罚训练。

差在哪差异是把复杂度从算法挪到系统:架构、缓存、部署、数据管线是变化所在,RL 配方本身不动。推断 对本看板的一条直接推论:D16 记录的两阶段后训练(隔离专家 → OPD 合并)在 V4.1 上被原样沿用并声明有效,这一配方的稳定性得到了第二个数据点。Engram 的 183 GiB 表也是部署门槛的主要来源——SGLang 把它卸载到主机后 KV 容量 +36%。

14判断与下一步

可搬走的三条判断

一、KV 压缩的第四个维度已经用掉。 条目(MLA)、精度(FP8)、序列(CSA/HCA)、层(CSA2)——四代模型各切一个数量级,V4.1 用的是最后一个还没用过的维度。下一代要再降一个量级,只能在"多少 token 合成一条"上更激进,或者接受更强的近似。

二、在昇腾上"能跑"与"跑出 890 字节"是两件事。 报告明言 FP4 main KV "不要求硬件原生支持该格式的矩阵乘,保持跨硬件平台兼容",这对昇腾本是好消息;但本站从源码核实的三点说明收益尚未兑现:① vLLM-Ascend 支持矩阵里 V4.1-Flash 只在 A2/A3 表(W8A8),而 V4-Flash 与 V4-Pro 各有一行 Ascend 950 并注明"Native mixed MXFP8/MXFP4 weights"——上一代已吃上 950 的原生 MXFP4,这一代还没有;② SGLang 的 Ascend 原生 DSV4 后端(约 95 KB)对 fp4 的引用数为 0,其 indexer KV 在新一代上是 FP8、更早的是 INT8;③ 两种 FP4 布局不兼容——DeepSeek 用 E4M3 scale/每 16 通道且 RoPE 维一并量化,昇腾现有 V4 核按 64 宽分组量化 nope、保留 64 维 RoPE 不量化(kv_quant_mode = 1, tile_size = 64, rope_head_dim = 64),而 950 的 MXFP4 是 E8M0/每 32。要补的三项按优先级:E2M1 反量化核与 288 字节页布局、按 kv_source_layer_ids 而非按层的 KV 分配、"部分层只跑尾部 128 token"的 prefill 调度。另外教程把 enable_npugraph_ex 与 enable_static_kernel 都设为 false,CSA2 静态模式最适合的整图融合这条收益目前完全未取。

三、harness 即分数现在有三个来源的样本。 D39/D40 的厂商适配层、D41 的开源 harness、本篇的厂商自证加第三方中立重跑(90.6 对 74.53)。任何国产模型的 agent 评测,不披露 scaffold、努力档、N 与 max_steps 的分数不应被引用;DeepSeek 的表 4 是可直接照抄的披露模板。
